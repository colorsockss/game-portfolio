# MMORPG 게임 설계

MMORPG 포트폴리오(`mmo/`)가 어떤 게임이고 각 시스템을 어떻게 만들지 적은 문서입니다. 무엇을 언제 만드는지는 [backlog.md](backlog.md)에, 이미 만든 것의 실제 구조와 규칙은 [MANUAL](../MANUAL.md)에 있습니다. 만들면서 이 문서와 달라지면 이 문서를 고칩니다.

## 방향

**리니지 라이크에 생활 콘텐츠 한 줄기를 더한 MMORPG**입니다(2026-11-10 정함).

**클라이언트 포트폴리오입니다**(2026-11-10 정함). 서버는 프로세스 하나로 두고, 화면보다 서버의 일이 큰 콘텐츠(거래소)는 넣지 않습니다. 서버에서는 MMO라서 꼭 해야 하는 것(서버 판정, 시야, 저장)과 그 최적화(틱 시간, 송신량, 사람이 몰린 곳)까지 합니다.

- 열린 필드에서 대상을 정해 몬스터를 잡고, 장비를 얻고 강화해 강해집니다.
- 마을 밖에서는 다른 플레이어를 공격할 수 있고(PK), 그 대가로 성향과 사망 페널티가 있습니다.
- 채집한 재료로 물약과 장비를 만듭니다.

조준형 액션(검은사막 방식)은 고르지 않았습니다. 그 난이도는 애니메이션에 맞춘 판정과 큰 월드에 있고 둘 다 에셋에 달려 있는데, 이 저장소는 직접 만든 것이나 CC0만 넣습니다. TCP와 20Hz 틱, 서버 판정, 많은 인원이 한 필드에 있는 구조는 대상 지정 전투와 맞습니다.

### 흐름

```
사냥 → 경험치·골드·아이템 → 레벨·장비·강화 → 더 센 사냥터·필드 보스
                     ↑                               ↓
채집 → 제작 ──────────┘                    PK(사냥터와 보스의 경쟁)
```

### 넣는 것

| 영역 | 콘텐츠 |
| --- | --- |
| 캐릭터 | 계정(로그인 ID) 하나에 캐릭터 4개까지, 캐릭터 만들기와 선택, 직업 둘(기사: 근접, 마법사: 원거리 마법) |
| 월드 | 걸어서 이어지는 필드 하나(마을, 사냥터 3곳, 채집지, 보스 자리), 길을 막는 건물·나무·바위·울타리, 안전 지대 |
| 전투 | 대상 지정 기본 공격, 직업마다 스킬 6개(두 직업을 합쳐 피해, 범위, 강화, 상태 이상, 회복, 소환. 직업마다의 구성은 [전투](#전투)), 주인을 따라다니며 함께 싸우고 맞는 소환수, 벽에 막히는 공격과 발사체, 자동 사냥 |
| 몬스터 | 일반 몬스터(선공·비선공), 벽을 돌아가는 길찾기, 필드 보스 |
| 성장 | 레벨, 장비 6칸(무기는 직업별, 방어구는 공용), 강화(확률과 파괴), 스킬 배우기 |
| 아이템 | 등급, 인벤토리와 창고, 소모품, 바닥에 떨어지는 드롭, NPC 상점, 따라다니며 드롭을 줍는 펫 |
| 함께 | 채팅, 파티 |
| 겨루기 | PK, 성향, 사망 페널티, 경비병 |
| 생활 | 채집, 제작 |
| 안내 | 퀘스트(잡기, 모으기, 만들기, 레벨, 장비), 목표까지 자동으로 걷기 |

### 범위 밖

- 운영과 이벤트: 우편, 공지, 출석, 이벤트, 랭킹, 쿠폰, 운영자 도구
- 결제, 광고, 외부 SDK. 로그인은 텍스트 ID입니다.
- 서버 선택, 채널, 인스턴스 던전, 서버 프로세스 여러 개(로그인 서버나 채팅 서버를 따로 두는 것 포함)
- 캐릭터 꾸미기(얼굴, 머리, 색), 방어구에 따라 바뀌는 겉모습(무기만 바뀝니다), 세 번째 직업부터(궁수 등), 캐릭터 지우기
- 명중·회피, 무게, 인벤토리 정렬과 인벤토리 칸 옮기기
- 친구 목록, 변신, 인형, 컬렉션
- 거래소와 개인 거래. 화면은 목록 하나인데 서버의 일(매물, 정산, 무결성)이 커서 뺐습니다. 아이템은 바닥에 떨어뜨려 건넬 수 있습니다
- 길드와 길드전
- 공성전, 탈것
- 펫의 성장과 먹이, 싸우는 펫, 소환수에게 내리는 명령, 소환수에게 쓰는 회복과 강화. 펫은 줍기만 하고, 소환수는 주인의 대상만 칩니다
- 낚시, 하우징, 무역
- 조준형 액션 전투, 스킬을 끌어서 조준하기
- 높이가 있는 지형, 건물 안, 계단, 다리. 땅은 평지이고 건물은 들어갈 수 없는 덩어리입니다
- 걷지는 못하지만 마법은 지나가는 칸(물, 낮은 울타리). 칸은 걸을 수 있는 것과 없는 것 둘뿐입니다
- 월드를 여러 존으로 나눠 따로 계산하기(포털로 잇는 존, 경계에 개체의 사본을 두는 심리스 존). 필드 하나를 한 스레드가 계산합니다

## 구조 원칙

- **서버가 판정합니다.** 전투, 성장, 아이템은 서버만 계산하고 클라이언트는 입력을 보내고 결과를 보여 줍니다. 이동만 클라이언트가 위치를 정하고 서버가 속도, 범위, 벽을 지나지 않았는지를 검증합니다(되돌림은 `PositionReset`. 벽의 규칙은 [공간](#공간)). 되돌림에 쓰는 `ack`의 정의는 [MANUAL의 패킷 정의](../MANUAL.md#패킷-정의)에, 속도를 검증하는 이동 예산의 정의는 [MANUAL의 서버](../MANUAL.md#서버)에 있습니다.
- **월드는 틱 스레드 하나만 읽고 고칩니다.** 잠금이 없고, 한 틱 안의 확인과 쓰기는 늘 한 동기 구간입니다. 소켓 쪽은 큐에 넣고 꺼내기만 합니다. 줍기처럼 여럿이 같은 것을 노리는 요청도 틱 안에서 들어온 순서대로 처리해 한 명만 성공합니다.
- **시간은 틱 번호로 셉니다.** 쿨다운, 시전, 버프, 리스폰, 선공 표시는 모두 "끝나는 틱"으로 가지고, 데이터의 밀리초는 읽을 때 틱 수(올림)로 바꿉니다. 시스템은 시계를 읽지 않고 틱 번호만 받으므로 틱을 손으로 돌리는 테스트가 됩니다. 틱이 밀릴 때의 규칙은 [과부하 때](#과부하-때)에 있습니다. 틱 번호는 서버가 다시 뜨면 0부터라 저장하지 않습니다.
- **난수는 서버만 굴립니다.** 피해, 드롭, 강화의 난수는 서버가 주입받은 `Random`에서 나오고, 테스트는 씨앗을 고정합니다.
- **기능 하나를 세로로 끝냅니다.** 계약(`packets.proto`) → 데이터 테이블 → 서버와 서버 테스트 → Unreal의 엔진 없는 코드와 테스트 → Unreal 화면 순서입니다. 서버와 엔진 없는 코드는 엔진 없이 테스트합니다.
- **세 구현의 답은 비교 벡터로 맞춥니다.** 비교 벡터는 서버의 테스트가 규칙마다 입력과 기대하는 답을 적어 낸 텍스트 파일입니다. `shared/`에 커밋하고, 두 클라이언트의 엔진 없는 테스트가 그 파일로 자기 구현의 답을 확인합니다.
- **계약은 `packets.proto` 하나입니다.** 패킷 번호는 기능마다 범위 하나를 쓰고([패킷 범위](#패킷-범위)), 서버와 두 클라이언트가 맞춰야 하는 수는 `Constant` enum 값입니다. 패킷의 형식에 묶인 수와 서버가 검증하고 클라이언트의 화면도 쓰는 수(틱, 좌표의 단위, 최대 이동 속도, 계정의 캐릭터 수, 파티의 최대 인원 5, 퀵슬롯의 수 8)는 `packets.proto`의 `Constant` enum에, 밸런스의 수는 `Constants` 테이블에 둡니다([데이터 테이블](#데이터-테이블)). 값이 같은 상수를 더할 때는 enum에 `allow_alias`를 켭니다.
- **필드 위의 것은 모두 같은 개체입니다.** 플레이어, 몬스터, 소환수, NPC, 채집물, 바닥 아이템이 개체 번호 공간, 시야 칸, `EntitiesEnter`·`EntitiesLeave`·`EntityMoves`를 함께 씁니다.
- **수치는 데이터에 둡니다.** 몬스터, 스킬, 아이템, 레벨, 확률, 시간은 `data/`의 xlsx가, 맵에 놓인 것은 `data/`의 텍스트 파일이 원본이고([월드](#월드)) 서버와 두 클라이언트가 같은 생성물을 읽습니다. 코드에는 틱 수 같은 구조의 상수만 둡니다. 이 문서의 수치는 처음 넣을 값이고 테이블에서 고칩니다. data-tool과 맵 생성기가 생성물 전체(테이블과 맵)의 해시(SHA-256의 앞 8바이트)를 내고 클라이언트가 `Login`에 실어 보내, 서버의 것과 다르면 로그인을 거절합니다. 프로토콜 버전은 패킷만 보므로, 데이터만 바뀐 배포에서 옛 클라이언트가 틀린 상점과 쿨다운, 옛 벽을 보이는 것을 막습니다.
- **클라이언트는 연결 → 세션과 월드 모델 → 화면으로 나눕니다.** 패킷은 월드 모델에 먼저 반영하고, 화면(액터, 위젯)은 그것을 읽기만 합니다. 월드 모델과 판단 코드(보간, 쿨다운, 자동 사냥)는 엔진 타입 없는 코드라 엔진 없이 테스트하고, Unity로 옮길 때 그대로 C#이 됩니다.
- **다른 개체는 서버 틱 번호로 보간합니다.** TCP가 패킷을 몰아서 전해도 `EntityMoves.tick`의 간격으로 다시 펴서 두 틱(100 ms) 늦게 그리고, 이동은 바뀔 때만 오므로 마지막 기록 뒤는 알려 준 속도로 이어 그립니다(알리는 규칙은 [공간](#공간)의 이동 알림). 클라이언트는 `EnterWorldResult`, `Pong`, `EntityMoves`에 실린 틱 번호와 받은 때로 서버의 지금 틱을 어림하고, 쿨다운과 시전의 남은 시간도 그것으로 그립니다. 위치가 이어지지 않는 이동(귀환, 부활, 몬스터의 복귀 순간 이동, 소환수가 주인 곁으로 옮겨지는 것, 개발 명령의 순간 이동)에는 모두 순간 이동 표시를 달아 보내, 보간하지 않고 바로 옮깁니다. 옮겨진 본인에게는 `PositionReset`을 보냅니다(내 개체는 `EntityMoves`에 들어가지 않습니다).
- **저장은 틱 밖의 저장 스레드가 합니다.** 틱은 플레이어의 사본을 큐에 넣기만 하고 디스크를 기다리지 않습니다. 규칙은 [저장의 흐름](#저장의-흐름)에 있습니다.

## 기술 선택

무엇을 쓰고 왜 쓰는지, 무엇을 고르지 않았는지입니다. **상태**가 "있음"인 것은 이미 만들어져 있고 근거 수치는 [MANUAL](../MANUAL.md)에 있습니다. "계획"은 만들 때 확인하고, 달라지면 이 표를 고칩니다.

### 서버

| 무엇에 | 쓰는 것 | 이유 | 고르지 않은 것 | 상태 |
| --- | --- | --- | --- | --- |
| 언어 | C#(.NET 10) | Unity 클라이언트와 같은 생성 코드(`Packets.cs`)를 씁니다. 봇 2,000명의 틱이 15.4 ms라 예산(50 ms) 안입니다 | UnrealSharp로 Unreal까지 C#으로 맞추기(접음, Unreal은 C++) | 있음 |
| 동시성 | 틱 스레드 하나 + 연결마다 받기·보내기 작업, `ConcurrentQueue`로 넘김 | 월드를 한 스레드만 고쳐 잠금과 경쟁 상태가 구조에서 없습니다. 틱 계산은 한 코어로 충분하고 소켓만 여러 코어를 씁니다 | 존마다 스레드(걸어서 이어지는 필드를 나누면 경계 근처 개체의 사본과 넘겨주기가 필요함. 잰 한도가 목표보다 커서 나눌 까닭이 없음) | 있음 |
| 틱 | 20Hz 고정(`PeriodicTimer`) | 대상 지정 전투는 50 ms 판정이면 충분하고, 송신량은 틱 수에 비례합니다 | 30·60Hz(송신량 1.5–3배) | 있음 |
| 전송 | TCP(`NoDelay`), 한 틱의 패킷을 한 버퍼로 | 순서와 재전송을 만들지 않아도 됩니다. TCP/IP 머리(52바이트)가 패킷마다가 아니라 틱마다 붙습니다 | UDP와 직접 만든 신뢰 계층(손실 있는 망에서 낫지만 만들고 검증할 것이 많음. 패킷 형식이 전송과 따로임) | 있음 |
| 직렬화 | Protobuf 36.2(길이 구분 형식) | 정의 하나에서 protoc가 C#과 C++을 만들고, 필드를 더해도 옛 쪽이 건너뜁니다. 대가는 개체 하나 15바이트(고정 크기 9바이트보다 송신 +58%) | 직접 만든 고정 크기 형식(9바이트, 생성기를 유지해야 해서 지움), MessagePack(12바이트) | 있음 |
| 좌표 | 1/32 m 정수(zigzag varint), 방향 256단위 | 실수 대신 정수라 작고, 서버와 두 클라이언트의 값이 비트까지 같습니다 | `float` 좌표 | 있음 |
| 시야 | 32 m 격자의 시야 칸, 둘레 3×3개, 지난 틱과 비교해 들어옴·나감·움직임만 보냄 | 모든 쌍을 비교하지 않고 시야 칸 안만 봅니다. 움직이지 않은 개체는 보내지 않습니다 | 쿼드트리(이유는 [MMO 서버 기술과 적용 여부](#mmo-서버-기술과-적용-여부)) | 있음 |
| 느린 연결 | 연결마다 상한 있는 `Channel`(40틱) | 따라오지 못하는 클라이언트가 서버 메모리를 끝없이 쓰지 않게 2초 넘게 밀리면 끊습니다 | 상한 없는 큐 | 있음 |

### Unity 클라이언트

Unreal에서 정한 구조를 옮깁니다. 표의 줄은 Unreal 표를 따르고, 엔진에 맞춰 무엇으로 바뀌는지를 적습니다. Unreal 표의 플러그인 줄은 대응하는 것이 없어 뺐고, 언어와 빌드 줄을 더했습니다. 고르지 않은 것은 Unreal 표와 같아 적지 않습니다.

## 서버 구조

MMORPG 서버가 해야 하는 일과 그것을 이 서버가 어떻게 하는지입니다. 이미 만든 뼈대(연결, 틱, 이동, 시야, 저장)의 실제 규칙은 [MANUAL의 서버](../MANUAL.md#서버)에 있고, 여기에는 콘텐츠까지 다 든 서버의 구조를 적습니다.

### MMO 서버 기술과 적용 여부

MMO 서버에서 흔히 쓰는 최적화 기술을 조사해(2026-11-10) 넣을 것과 넣지 않을 것을 갈랐습니다. 오픈소스 MMO 서버(TrinityCore, L2J, rAthena, KBEngine)의 소스와 설정, 커뮤니티가 정리한 패킷 정의(테라), 엔진 문서(Unreal, Photon, BigWorld), Microsoft 문서, 책(ithare, Game AI Pro)을 읽은 결과입니다. "흔한 정도"는 몇 개의 자료가 쓰는지로 매겼습니다. GDC와 NDC의 발표는 읽지 못했습니다.

### 프로세스와 스레드

프로세스 하나가 월드 하나를 가집니다.

```
받기 작업(연결마다) ──┐                         ┌── 보내기 작업(연결마다)
받기 작업            ─┼→ 큐 → [ 틱 스레드 ] → ─┼── 보내기 작업
연결 받기            ─┘      월드를 혼자 고침    └── 저장 스레드
```

- **받기**: 연결마다 비동기 작업이 프레임을 읽어 패킷으로 만들고 큐에 넣기만 합니다. 월드는 건드리지 않습니다.
- **틱 스레드**: 20Hz로 돌며 월드를 혼자 읽고 고칩니다. 게임의 모든 판정이 여기서 납니다.
- **보내기**: 틱이 만든 버퍼를 연결마다 비동기 작업이 보냅니다. 느린 연결은 그 연결의 큐만 밀립니다.
- 받기와 보내기는 여러 코어를 쓰고(2,000명에 1.7코어), 틱 계산은 한 코어입니다(2,000명에 15.4 ms).

프로세스를 나누지 않는 이유는 둘입니다. 필드가 하나이고 잰 한도(이동만으로 약 6,000명)가 목표(시연 서버의 동접 수백 명)보다 큽니다. 그리고 클라이언트 포트폴리오라 서버 사이의 일을 만들지 않습니다. 넘으면 어떻게 나누는지는 [규모를 넘으면](#규모를-넘으면)에 있습니다.

실제 MMORPG는 서버를 나눕니다(2026-11-10 조사). 여기서는 그 일들이 한 프로세스 안에 있습니다.

### 틱의 차례

한 틱은 늘 같은 차례로 돕니다. 차례가 고정이라 같은 입력이면 같은 결과가 나고, 테스트가 틱을 손으로 돌릴 수 있습니다.

| 차례 | 하는 일 |
| --- | --- |
| 1. 입력 | 큐의 일(연결, 패킷, 끊김, 저장 스레드가 돌려준 불러오기 결과)을 들어온 순서대로 꺼내 검증하고 처리합니다. 이동, 공격의 시작과 멈춤, 인벤토리 요청, 진행 중인 일의 시작이 여기서 반영됩니다. 스킬 요청은 검증까지 하고, 비용은 시전 시간이 없는 스킬은 그 자리에서, 시전 시간이 있는 스킬은 발동할 때 뺍니다. 대상을 고르는 것은 클라이언트 안의 일이라 여기 오지 않습니다([전투](#전투)) |
| 2. 예약한 일 | 때가 된 일을 꺼냅니다(목록은 [예약한 일](#예약한-일)). 시전의 끝과 타격의 결과처럼 스킬과 공격의 결과를 내는 일은 전투 차례로 넘기고, 나머지(효과의 끝, 리스폰, 귀환·채집·제작의 끝 등)는 꺼낸 자리에서 합니다 |
| 3. 몬스터 | 몬스터의 상태(대기, 추적, 공격, 복귀)를 진행하고, 경비병([PK](#pk))과 소환수([몬스터](#몬스터))도 함께 돌립니다. 둘레 9개의 시야 칸에 플레이어가 없는 몬스터와 경비병은 재워 계산하지 않고, 깨어나면 하던 상태를 그대로 잇습니다. 소환수는 늘 주인 곁에 있어 잠들지 않습니다 |
| 4. 전투 | 다음 공격 틱이 된 기본 공격을 시작하고, 앞의 차례가 넘긴 스킬의 발동과 타격의 결과(피해, 효과)를 적용하고, 직선으로 나는 발사체를 옮기고 닿은 것을 맞히고, 죽음을 처리합니다(경험치, 드롭, 성향, 퀘스트). 시작과 타격을 나누는 규칙은 [전투](#전투)에 있습니다 |
| 5. 회복 | 체력과 마나를 채웁니다(1초마다). 펫의 줍기도 이 차례에서 합니다([아이템](#아이템)의 펫) |
| 6. 시야 | 플레이어마다 지난 틱과 비교해 들어옴·나감·움직임을 보내고, 이번 틱의 사건(공격과 스킬의 시작, 진행 중인 일, 피해, 효과, 죽음과 부활, 발사체, 범위 예고)과 표시 상태 변화, 1초마다 모은 체력을 받을 연결에 넣습니다(누가 받는지는 [전투](#전투)의 결과, 진행 중인 일, 발사체와 [개체](#개체)의 표시 상태) |
| 7. 저장 | 5초와 60초의 바뀜 표시가 된 플레이어의 사본을 묶어 저장 스레드의 큐에 넣습니다(내놓는 요청은 입력 차례에서, 무법자가 죽어서 떨어뜨린 것은 전투 차례에서, 나갈 때의 사본은 캐릭터가 월드에서 빠지는 차례에서 이미 넣음. [저장의 흐름](#저장의-흐름)) |
| 8. 보내기 | 연결마다 이번 틱의 패킷을 한 버퍼로 만들어 보내기 큐에 넣습니다 |

입력 차례의 요청은 자기 플레이어의 상태만 고칩니다. 예외는 파티의 요청(초대 수락, 떠나기, 내보내기)입니다. 파티는 여러 플레이어가 함께 가진 상태이기 때문입니다. 다른 개체를 고치는 결과(피해, 죽음, 효과 붙이기)는 전투 차례로 넘깁니다. 줍기처럼 입력 차례에서 남의 것을 고쳐야 하는 요청은 그 일을 마지막에 합니다(줍기: 인벤토리에 넣기 → 바닥 개체 지우기). 요청을 처리하다 난 예외를 그 플레이어만 끊고 끝낼 수 있는 까닭입니다([오류와 내려가기](#오류와-내려가기)).

### 코드의 구조

- **월드**: 개체와 격자를 가집니다. 개체 번호는 작게 둡니다. 몬스터와 채집물은 놓인 점마다 정해진 번호를 다시 나올 때도 쓰고, 바닥 아이템과 소환수는 사라진 지 10초가 지난 번호를 다시 쓰고, 플레이어의 번호는 다시 쓰지 않습니다. 번호가 작아야 varint가 짧습니다(200만을 넘으면 개체 하나가 2바이트 늘어 송신량이 약 13% 늡니다).
- **개체**: 종류가 여섯뿐이고 고정이라 클래스 계층으로 둡니다. 모든 개체가 공통 부분(번호, 위치, 시야 칸)을 가집니다. 그 위에 체력, 능력치, 효과, 전투 상태를 가지는 것은 플레이어, 몬스터, 소환수이고, 경비병은 체력 없이 공격력과 추적 상태만 가진 NPC입니다. 소환수는 그 위에 주인과 따라가기·추적의 상태를 가집니다. 펫은 개체가 아닙니다([아이템](#아이템)의 펫).
- **시스템**: 세션(코드의 `LoginSystem`), 이동, 스폰, 몬스터, 전투, 스킬, 발사체, 효과, 능력치, 회복, 시야, 저장, 성장, 드롭, 인벤토리, 상점, 파티, PK, 채집, 제작, 채팅, 퀘스트가 각각 클래스 하나입니다. 창고는 인벤토리 시스템이, 펫의 줍기는 드롭 시스템이, 소환수와 경비병은 몬스터 시스템이 맡습니다. 월드의 데이터를 고치는 코드만 있고 자기 상태는 거의 없습니다.
- **시스템 사이**: 묻는 것(칠 수 있는가, 구역이 어디인가)과 자기 개체의 능력치 재계산은 직접 부릅니다. 다른 시스템의 상태를 바꾸는 결과만 틱 안의 사건으로 잇습니다. 전투가 "죽음"을 내면 성장(경험치), 드롭, PK(성향), 퀘스트가 그것을 받습니다. 사건은 그 틱 안에서 차례대로 처리하고 다음 틱으로 넘기지 않습니다.
- **데이터**: 테이블은 서버가 뜰 때 읽어 바꾸지 않는 객체로 둡니다. 데이터를 바꾸려면 서버를 다시 띄웁니다.

### 예약한 일

- **쓸 때만 보면 되는 것**(쿨다운, 전투 상태)은 "끝나는 틱"을 필드로 두고 쓸 때 비교합니다. 틱마다 드는 비용이 없습니다.
- **끝나는 틱에 할 일이 있는 것**은 모두 틱 번호의 우선순위 큐(예약 큐)에 넣고, 틱마다 때가 된 것만 꺼냅니다.

| 예약하는 일 | 끝나는 틱에 하는 일 |
| --- | --- |
| 효과의 끝 | 효과를 떼고 능력치를 다시 구하고 바뀐 속도를 알림 |
| 선공 표시의 끝 | 이름 색이 바뀐 것을 알림 |
| 월드에 남은 캐릭터 빼기 | 전투 상태와 선공 표시가 끝나는 틱에 뺌. 죽었으면 그다음 틱에 뺌([세션](#세션)). 전투 상태 자체는 쓸 때 비교함 |
| 진행 중인 일(시전, 채집, 제작, 귀환)의 끝 | 확인을 다시 보고 끝냄([전투](#전투)) |
| 타격할 틱이 된 공격과 스킬의 결과 | 피해와 효과를 적용함([전투](#전투)) |
| 보스 범위 공격의 피해 | 예고 시간 뒤에 피해를 줌([몬스터](#몬스터)) |
| 리스폰 | 몬스터와 채집물이 놓인 점에 다시 나옴 |
| 죽은 몬스터와 소환수 사라짐 | 죽은 지 3초 뒤에 뺌 |
| 바닥 아이템 사라짐 | 남는 시간이 지나면 뺌([아이템](#아이템)) |
| 파티 초대의 만료 | 답이 없는 초대를 지움([파티](#파티)) |
| "닿을 수 없음"의 끝 | 5초 뒤에 표시를 지움([몬스터](#몬스터)) |
| 소환수의 남는 시간의 끝 | 소환수를 뺌([몬스터](#몬스터)의 소환수) |

- 끝나는 틱이 바뀌었거나(같은 효과를 다시 건 경우) 취소된(넘겨받기로 버린 빼기, 취소된 진행 중인 일, 죽거나 기절하거나 월드에서 빠진 공격자의 타격, 죽거나 복귀를 시작한 보스의 범위 공격, 답했거나 지워진 파티 초대, 사라진 개체의 일) 옛 예약은 꺼낼 때 버립니다. 같은 틱의 일은 넣은 순서대로 꺼내, 같은 입력에 같은 결과가 나게 합니다.

### 공간

- **시야 칸**: 32 m 격자 하나의 칸(시야 칸)을 시야, 범위 스킬의 대상 찾기, 직선으로 나는 발사체가 닿을 후보, 보스의 범위 공격, 몬스터와 경비병의 인식, 줍기(펫의 줍기 포함)와 NPC의 거리 확인, 몬스터와 경비병을 재우는 판단, 경험치를 나눠 받을 파티원 찾기, 주변 채팅에 함께 씁니다. 원 안의 개체를 찾을 때는 원이 걸친 시야 칸만 보고, 그 안에서 거리를 잽니다.
- **시야의 경계**: 개체가 시야에서 나가는 기준을 들어오는 기준보다 8 m 넓게 둡니다. 시야 칸의 경계를 오가는 개체가 틱마다 들어옴과 나감을 내지 않게 하려는 것입니다(들어옴은 이름과 상태를 다 실은 큰 패킷입니다). 여유 안에 남은 개체는 받은 연결의 목록([전투](#전투)의 결과)에 그대로 있어 사건과 상태가 계속 갑니다.
- **이동 알림**: 서버는 이동을 바뀔 때만 알리고 클라이언트가 그 사이를 이어 그립니다. 바뀔 때만 알리는 것은 서버가 다른 플레이어에게 알리는 쪽뿐이고, 클라이언트가 서버에 보내는 `Move`는 줄이지 않습니다(초당 20번까지, 움직이는 중 표시를 실음).
  - 플레이어의 이동은 출발, 방향 바뀜, 멈춤과 0.5초마다의 확인만 알립니다. 방향 바뀜은 마지막으로 알린 값에서 `yaw`가 8단위(약 11도) 넘게 달라졌을 때 알리고 4틱에 한 번까지입니다.
  - 플레이어의 멈춤을 알리는 때는 넷입니다. 움직이는 중 표시가 꺼진 `Move`가 왔을 때, 표시가 켜진 `Move`가 왔는데 위치가 바로 앞의 `Move`와 같을 때(벽에 막힘), 10틱 동안 `Move`가 없을 때, 서버가 그 캐릭터를 세운 때(기절, 죽음, 연결이 떨어져 월드에 남음. 그 틱에 알립니다)입니다. 틱마다가 아니라 `Move`끼리 견주어, 프레임이 낮은 정상 클라이언트가 멈춤과 출발을 되풀이하지 않게 합니다.
  - 몬스터는 목적지 하나가 아니라 경로의 다음 꺾이는 점과 속도를 알립니다. 쫓는 대상이 움직여 목적지가 바뀐 것은 10틱에 한 번까지만 알립니다. 꺾이는 점에 닿아 다음 점으로 바뀐 것은 그때마다 알립니다.
  - 감속이 붙거나 떨어져 속도가 바뀌면 `EntityMoves`의 속도로 알립니다.
  - 클라이언트는 알려 준 속도로 이어 그리되, 격자를 보고 막힌 칸 앞에서 멈춥니다.
  - 알리는 빠르기는 최대 속도(몬스터는 그 속도)에 감속을 곱한 값입니다. 그래서 클라이언트의 내 캐릭터는 가속 없이 출발하고 멈추며, 가상 조이스틱도 기울기와 관계없이 최대 속도로 걷습니다. 가속하는 동안이나 느리게 걷는 동안이 있으면 다른 화면이 알린 빠르기로 앞질러 그리고 확인마다 뒤로 당겨집니다.
- **`FieldMap`**: 벽은 1 m 칸의 배열 하나에 있습니다. 격자 생성물에는 칸마다 막힘만 들고, 서버와 클라이언트의 월드 모델이 그 생성물을 읽습니다([월드](#월드)의 맵 원본). 구역은 격자 생성물에 넣지 않고 `FieldMap`이 `Zones` 테이블에서 직접 폅니다. 좌표를 칸으로 바꿀 때는 내림(floor)을 써서 음수 좌표도 한 칸에 하나씩 대응합니다. 격자 밖의 칸은 벽으로 봅니다(누구도 걸을 수 없고 선도 막습니다. 칸이 내림이라 정확히 +300 m는 격자 밖입니다). 칸은 걸을 수 있는 것과 없는 것 둘뿐이고, 개체(플레이어, 몬스터, 소환수, NPC, 채집물)는 칸을 막지 않습니다. 그래서 몬스터와 캐릭터가 한 점에 겹칠 수 있고, 겹쳐 보이는 것은 받아들입니다. 걷는 쪽은 플레이어와 몬스터 둘이고, 몬스터에게는 안전 지대의 칸도 걸을 수 없는 칸입니다([몬스터](#몬스터)). 경비병과 소환수는 플레이어와 같은 걷는 쪽이라 안전 지대를 걷습니다. 벽인지는 걷는 쪽과 상관없이 같습니다.
- **선 검사**: 두 점을 잇는 선이 지나는 칸을 차례로 보는 함수가 둘입니다. 둘 다 선이 칸의 모서리를 정확히 지나면 그 모서리에 닿은 칸 가운데 하나라도 걸릴 때 걸린 것으로 봅니다. 그래서 대각선으로 맞닿은 두 벽 사이로는 지나지 못합니다. 가장자리의 경우도 세 구현이 같은 답을 내게 정합니다. 선이 칸의 변 위를 따라가면 지나는 모서리마다 이 모서리 규칙을 적용해 양쪽 칸을 모두 봅니다. 두 끝점의 칸도 봅니다. 끝점이 칸의 경계 위에 있어도 선이 그 끝점에서만 닿고 들어가지 않는 칸은 보지 않습니다(벽 곁의 경계까지 걸어오고 거기서 떠날 수 있게. 2026-11-13 정함). 길이가 0인 선은 그 칸만 봅니다. 계산은 정수로만 합니다.
  - **`FieldMap.HasLine(a, b)`**: 벽만 봅니다. 선이 지나는 칸에 벽이 하나라도 있으면 막힌 것입니다. 거리를 보는 확인(아래의 벽 너머)과 드롭을 놓을 자리(몬스터의 드롭과 죽은 플레이어가 떨어뜨린 것. [아이템](#아이템), [PK](#pk))가 씁니다. 안전 지대의 칸은 벽이 아니라서 이 선을 막지 않습니다.
  - **`FieldMap.CanWalkLine(a, b, 걷는 쪽)`**: 선이 지나는 칸이 그 걷는 쪽(플레이어, 몬스터)에게 모두 걸을 수 있는 칸인지를 봅니다. 플레이어의 이동 검증, 몬스터의 곧게 가기·복귀·배회할 점 고르기, 몬스터와 채집물의 스폰 흩기([몬스터](#몬스터)), A*가 찾은 길을 줄일 때(아래의 길찾기), 경비병의 곧게 가기([PK](#pk)), 소환수의 따라가기([몬스터](#몬스터)), 클라이언트의 펫 자리([아이템](#아이템))가 씁니다. 플레이어 쪽의 답은 `HasLine`과 같고, 몬스터 쪽은 안전 지대의 칸을 지나는 선도 걸을 수 없다고 답합니다.
- **이동 검증**: 서버는 지난 위치에서 새 위치까지를 `CanWalkLine`(플레이어 쪽)으로 보고, 걸을 수 없으면 `PositionReset`으로 되돌립니다. 서버는 캐릭터를 점으로 봅니다. 클라이언트의 충돌 상자는 막힌 칸의 경계 그대로라 캡슐의 중심이 벽에서 반지름만큼 떨어집니다. 클라이언트가 더 엄격하므로 정상 클라이언트는 되돌려지지 않습니다. 내 캐릭터를 벽 앞에 세우는 것은 엔진의 충돌이고, 월드 모델의 격자는 길찾기, 대상에게 갈 곳의 선, 펫의 자리, 다른 개체를 이어 그리는 데 씁니다(위의 이동 알림).
- **벽 너머**: 대상에 닿는지를 거리로 보는 아래의 확인은 모두 `HasLine`도 함께 봅니다(소환수가 주인에게서 떨어진 거리처럼 닿는지를 보지 않는 거리는 선을 보지 않습니다). 기본 공격(플레이어, 몬스터, 경비병, 소환수의 것 모두), 스킬의 대상, 범위 스킬(중심에서 대상까지), 직선으로 나는 발사체(틱마다 옮긴 경로), 몬스터와 경비병의 인식, 줍기(펫의 줍기 포함), NPC(상점, 창고, 제작, 퀘스트), 채집, 보스의 범위 공격(중심에서 대상까지. 벽 뒤에 숨으면 피합니다)입니다. 시야(누가 보이는가)에는 쓰지 않아 이름표는 벽 너머로도 보입니다. 줍기, NPC, 채집은 사거리(3 m) 안이어도 선이 막혔으면 `FailReason`의 "막힘"으로 실패합니다. 기본 공격과 스킬에서 선이 막혔을 때 어떻게 되는지는 [전투](#전투)에 있습니다.
- **길찾기**: 같은 격자에서 A*로 찾습니다. 8방향으로 가고, 대각선으로는 양옆 두 칸이 모두 열려 있을 때만 갑니다. 휴리스틱은 옥타일 거리이고, 우선순위가 같으면 비용이 큰(도착에 가까운) 칸을 먼저 꺼냅니다(빈 들판에서 넓게 퍼지지 않게. 실제 맵의 끝에서 끝까지 닫는 칸이 상한을 넘던 것이 약 18,300칸으로 줄었습니다). 찾은 길은 곧게 갈 수 있는 구간(`CanWalkLine`을 통과하는 구간)을 합쳐 꺾이는 점의 목록으로 줄입니다.
  - 서버(몬스터, 경비병, 소환수)와 클라이언트의 엔진 없는 코드에 각각 두고, 엔진의 내비메시는 쓰지 않습니다. 서버의 A*는 걷는 쪽을 받고, 클라이언트의 A*는 플레이어 쪽만 씁니다. 클라이언트에서는 공격하러 가기, 줍기, NPC, 채집, 자동 사냥, 눌러서 이동, 퀘스트 목표까지 걷기가 같은 길찾기를 씁니다.
  - 서버는 놓인 점 둘레의 정한 범위 안의 칸만 봅니다(추적과 복귀의 범위는 [몬스터](#몬스터)). 소환수는 주인 둘레 20 m 안의 칸만 봅니다(최대 약 1,260칸. 계산한 값). 클라이언트는 한 번에 살피는 칸 수에 상한(20,000칸. 길찾기의 구조 상수라 클라이언트의 코드에 둡니다)을 두고, 넘으면 길이 없는 것으로 봅니다.
  - 길은 길이가 같아도 경로가 다를 수 있습니다. 그래서 서버와 두 클라이언트가 같은 답을 내야 하는 것은 칸 조회와 두 선 검사이고(비교 벡터. 걷는 쪽은 플레이어 쪽만 넣습니다), 길은 클라이언트가 낸 길의 구간마다 클라이언트의 `CanWalkLine`(비교 벡터로 서버와 같은 답을 내는 것을 본 것)을 통과하는지를 봅니다. 길이 있는지 없는지가 서버와 같은지는 두 쪽의 상한에 걸리지 않는 작은 시험 맵에서 봅니다.

길찾기의 방식을 고른 비교입니다. 격자 A*의 시간은 시험 구현으로 잰 값이고([성능 수치](performance.md)), 내비메시는 재지 않았습니다.

### 요청 검증

클라이언트가 보내는 것은 "하고 싶은 것"뿐이고, 되는지는 서버가 봅니다.

| 확인하는 것 | 예 |
| --- | --- |
| 순서와 상태 | 로그인 전이나 월드에 들어가기 전의 요청, 죽었거나 기절한 동안의 요청(기절한 동안에는 아무 행동도 할 수 없어 연결 확인, 공격 멈춤, 채팅, 개발 명령, 나가기만 받고 나머지는 실패 알림으로 답합니다(공격 멈춤은 하는 것이 아니라 그만두는 것이라 받습니다. 받지 않으면 기절한 동안 풀린 대상을 기절이 끝난 뒤 다시 칩니다). `Move`는 되돌립니다. 죽은 동안에는 받는 것에 부활을 더합니다), 진행 중인 일이 있는 동안의 요청([전투](#전투)) |
| 거리와 벽 | 스킬의 사거리, 줍기, NPC, 채집물. 거리를 보는 확인은 그 사이의 선이 벽에 막혔는지도 봅니다([공간](#공간)) |
| 가진 것과 자격 | 아이템과 수량, 골드, 배운 스킬, 마나, 장비와 스킬북의 직업과 필요 레벨 |
| 시간 | 쿨다운, 공격 간격, 물약 쿨다운, 이동 예산 |
| 관계와 구역 | 안전 지대, 레벨 10 미만, 파티원(`CanAttack`. [PK](#pk)), 대상이 복귀 중인 몬스터인지(`CanAttack`과 따로 봅니다. [전투](#전투)), 드롭의 주인 |
| 빈도와 크기 | 초당 패킷 수(토큰 버킷), 채팅 간격, 패킷 256바이트 |

어긋난 요청은 셋으로 나눕니다.

- **실패 알림**: 지연 때문에 정상 클라이언트도 보낼 수 있는 것(방금 죽은 대상을 공격, 이미 주운 아이템을 줍기)은 실패를 알리고 넘어갑니다. 요청 번호가 있는 요청은 `RequestResult`(요청 번호, 결과)가 답하고, 결과는 `FailReason`입니다(0이면 성공). 요청 번호가 없는 요청(공격 시작, 스킬 사용, 채집의 시작, 퀵슬롯 바꾸기, 창고 열기, 펫 부르기와 넣기, 부활, 파티, 채팅)의 실패는 `ActionFailed`가 알리고, 이유와 함께 어느 요청의 실패인지(공격, 스킬, 채집, 퀵슬롯, 창고, 펫, 부활, 파티, 채팅)를 싣습니다. 개발 명령은 채팅창에서 보내므로 그 실패는 채팅의 실패로 갑니다. 어느 요청이 요청 번호를 싣는지는 [아이템](#아이템)의 요청 번호에 있습니다. 클라이언트는 둘 다 `FailReason`마다의 글을 알림 층에 띄웁니다.
- **되돌림**: 이동이 어긋나면 `PositionReset`으로 서버의 위치를 알립니다.
- **끊기**: 정상 클라이언트가 보낼 수 없는 것(읽을 수 없는 패킷, 서버가 보내는 패킷, 없는 스킬 번호, 로그인 전이나 월드에 들어가기 전에 온 월드의 요청)은 `KICK_REASON_MALFORMED_PACKET`으로 끊습니다(상태에 맞지 않는 요청을 끊는 것은 있음). 정상 클라이언트는 `LeaveWorld`를 보낸 뒤 월드의 요청을 보내지 않습니다. 요청의 빈도는 연결마다 토큰 40개의 버킷을 두고 초당 30개를 채워 제한하고, 버킷이 비면 요청을 버립니다. 요청을 버리기 시작한 틱부터 3초 동안 버리는 일이 이어지면 `KICK_REASON_RATE_LIMITED`로 끊고, 1초 동안 버린 것이 없으면 다시 셉니다(처음 값. 정상 클라이언트는 초당 20번의 `Move`와 행동 몇 번을 보냅니다). 끊긴 클라이언트가 다시 붙는지는 [세션](#세션)의 다시 연결에 있습니다.

요청 번호를 실은 요청은 버릴 때도 `RequestResult`로 실패를 답합니다. 답이 없으면 클라이언트가 그 인벤토리 칸을 계속 기다립니다. `Move`도 같은 버킷에서 셉니다. 버킷의 크기(40개)가 초당 20번의 `Move`보다 넉넉해, 망이 몰아서 전한 `Move`가 한꺼번에 와도 다른 요청이 버려지지 않습니다.

채팅 입력의 글이 `/`로 시작하면 클라이언트가 채팅이 아니라 개발 명령(`DevCommand`. 세션 범위의 패킷)으로 보냅니다. 개발 옵션(`--dev`)을 켠 서버만 명령을 실행하고, 켜지 않은 서버는 끊지 않고 실패 알림으로 답합니다(`FailReason`의 "쓸 수 없는 명령"). 명령은 순간 이동, 몬스터 부르기, 레벨·아이템·골드 주기, 성향 정하기입니다. 순간 이동은 자리가 막힌 칸이거나 필드 밖이면, 몬스터 부르기는 막힌 칸이면 실패합니다. 개발 명령은 월드 안에서만 받고, 들어가기 전에 온 것은 다른 월드의 요청처럼 끊습니다. 명령으로 부른 몬스터는 죽으면 다시 나오지 않습니다.

### 세션

- **로그인**: 텍스트 ID가 계정입니다. 실제 서비스라면 인증 서버가 준 토큰을 여기서 검증하지만 범위 밖입니다. 그래서 시연 서버에서는 남의 ID를 아는 사람이 그 계정의 캐릭터로 들어올 수 있습니다. 알고 두는 대가이고 README에 적습니다. 프로토콜 버전이나 데이터 해시가 달라 거절된 클라이언트는 새 빌드를 받으라는 안내와 받는 곳을 보입니다. 받는 곳은 저장소의 릴리스 페이지 주소이고 클라이언트의 설정에 둡니다.
- **캐릭터 선택**: 캐릭터 목록(`CharacterList`, 4칸까지)은 클라이언트가 요청하지 않고 서버가 로그인, 만들기, `LeaveWorld` 뒤에 보냅니다. 클라이언트는 캐릭터를 만들거나 하나를 골라 월드에 들어가고(`EnterWorld`), 그 답은 `EnterWorldResult`입니다. 들어가기 전의 연결은 월드에 개체가 없고 만들기, 들어가기, 연결 확인만 보낼 수 있습니다. 게임 중에 설정 창에서 캐릭터 선택으로 돌아갈 수 있습니다(`LeaveWorld`. 규칙은 아래의 로그아웃과 같습니다).
- **들어오는 자리**: 새 캐릭터는 마을의 부활 지점에서 시작합니다. 무작위 자리에서 시작하는 것은 부하 측정용 서버 옵션(`--spawn-half-extent`)이고, 막힌 칸이 뽑히면 다시 뽑습니다. 저장된 위치가 막힌 칸이거나 필드 밖이면 마을의 부활 지점으로 옮깁니다. 무법자도 같습니다. 죽은 것이 아니라 맵이 바뀐 탓이기 때문입니다. 들어올 때 옮기는 것이라 다른 연결은 옮긴 자리의 `EntityEnter`만 받고, 순간 이동 표시는 달지 않습니다.
- **같은 계정의 재로그인**: 같은 계정이 다시 로그인하면 예전 연결을 끊습니다(`KICK_REASON_DUPLICATE_LOGIN`). 새 연결은 캐릭터 선택부터 합니다.
- **월드에 남는 캐릭터**: 전투 상태이거나 선공 표시가 있는 캐릭터는 끊기거나 나가도(로그아웃, `LeaveWorld`, 재로그인으로 끊긴 예전 연결) 그것이 끝날 때까지 월드에 남아 맞습니다. 끊어서 죽음을 피하지 못하게 하려는 것입니다. 연결이 떨어질 때 진행 중인 일은 취소되고([전투](#전투)) 파티에서 빠지며([파티](#파티)) 소환수는 사라지고([몬스터](#몬스터)의 소환수), 남아 있는 동안 기본 공격과 펫의 줍기는 멈춥니다. 전투 상태와 선공 표시가 끝나는 틱에 월드에서 빠지고([예약한 일](#예약한-일)), 죽으면 그다음 틱에 빠집니다(죽음 사건이 나감보다 먼저 가게). 연결이 떨어질 때 이미 죽어 있는 캐릭터는 남지 않고 바로 빠집니다. 남은 캐릭터는 동접 상한에 세지 않습니다. 연결이 없는 캐릭터는 귓속말과 파티 초대의 대상이 되지 않습니다.
  - **넘겨받기**: 남아 있는 캐릭터와 같은 캐릭터로 `EnterWorld`하면 데이터베이스에서 읽지 않고 메모리의 캐릭터에 연결만 갈아 끼웁니다. 남아 있는 캐릭터는 나갈 때의 사본을 아직 넣지 않아([저장의 흐름](#저장의-흐름)), 읽으면 마지막 저장 뒤의 변화가 되돌아가기 때문입니다. 개체 번호가 그대로라 몬스터의 대상과 남이 공격하던 대상이 이어집니다. `ack`와 요청 번호는 0부터 다시 시작하고, 넘겨받은 연결에는 처음 들어온 것처럼 인벤토리와 주변 개체를 비롯한 모든 상태를 다시 보냅니다. 죽어서 그다음 틱에 빠지기를 기다리는 캐릭터도 죽은 채로 넘겨받고(빼기는 버립니다), 클라이언트는 사망 화면부터 띄웁니다.
  - **같은 계정의 다른 캐릭터**: 남아 있는 캐릭터가 있는 동안 그 계정이 다른 캐릭터로 `EnterWorld`하면 거절하고, 다른 캐릭터가 아직 월드에 있다는 이유를 알립니다. 캐릭터를 바꿔 들어와 싸움에서 빠져나가지 못하게 하려는 것입니다.
- **끊김**: 15초 동안 아무것도 오지 않으면 끊습니다(있음). 로그인 시간 제한(10초)은 `Login`을 받기 전까지만 셉니다.
- **다시 연결**: 뜻하지 않게 끊긴 클라이언트는 다시 붙습니다(망이 끊긴 것, 서버가 무응답으로 끊은 것 포함). 간격은 1초부터 두 배씩 늘려 30초까지이고 2분 동안 시도합니다(배포로 서버가 다시 뜨는 시간보다 길어야 합니다). 2분 동안 붙지 못하면 로그인 화면으로 돌아갑니다. 붙으면 같은 ID로 로그인해 들어가 있던 캐릭터로 `EnterWorld`를 다시 보냅니다. 캐릭터 선택에서 끊겼으면 로그인까지만 합니다. 다시 붙는 동안 화면은 "다시 연결 중"을 띄우고 월드를 그대로 두며, 이동과 요청의 입력을 막습니다. 다시 붙은 뒤 자동 사냥은 꺼져 있습니다. 앱이 백그라운드에서 돌아왔을 때 15초가 지났으면 연결을 바로 닫고 다시 붙습니다. 서버 오류(`KICK_REASON_SERVER_ERROR`)나 서버가 내려가서 끊긴 것도 다시 붙습니다. 내가 닫았거나, 끊긴 이유가 중복 로그인, 잘못된 패킷, 빈도 제한이거나, 로그인이 동접 상한이나 프로토콜 버전·데이터 해시로 거절됐으면 다시 붙지 않고 이유를 알립니다(버전과 해시의 안내는 위의 로그인).
- **로그아웃**: 클라이언트가 나가겠다고 보내면(`Logout`) 캐릭터를 저장해 월드에서 빼고 닫습니다. `Logout`은 월드 안에서만 보내고, 캐릭터 선택에서는 연결을 닫습니다. 게임 종료는 월드 안이면 로그아웃과 같은 길을 거칩니다. 전투 상태이거나 선공 표시가 있으면 위의 규칙대로 캐릭터가 남습니다. 캐릭터 선택으로 돌아가는 `LeaveWorld`도 같습니다. 다만 연결은 닫지 않고 캐릭터 목록을 다시 보냅니다.
- **죽은 채 빠진 캐릭터**: 저장된 체력이 0이면 죽은 채 빠진 것입니다. 들어올 때 부활 지점(무법자는 무법자의 부활 지점)에서 부활한 상태로 시작합니다. 페널티는 죽을 때 이미 적용됐습니다. `EnterWorldResult`가 이 경우임을 싣고, 클라이언트는 그것으로 부활했다는 알림 한 줄을 띄웁니다([화면](#화면)의 알림).
- **다시 들어와도 남는 것**: 성향은 저장되어 남습니다. 쿨다운, 효과, 선공 표시는 저장하지 않아 월드에서 빠질 때 사라집니다. 전투 상태나 선공 표시가 있으면 캐릭터가 월드에 남으므로, 접속을 끊어 지울 수는 없습니다.

### 저장의 흐름

- **메모리가 원본입니다.** 월드에 들어올 때(`EnterWorld`) 캐릭터를 읽어 메모리에 두고, 틱은 메모리만 읽고 고칩니다. 데이터베이스는 서버가 죽어도 남기려는 것입니다.
- **큐와 저장 스레드**: 틱은 플레이어의 사본을 큐에 넣기만 하고 디스크를 기다리지 않습니다. 큐의 단위는 묶음(사본의 목록)이고, 저장 스레드가 들어온 순서대로 묶음 하나를 한 트랜잭션으로 씁니다.
- **언제 넣나**: 플레이어마다 바뀜 표시를 둘(5초, 60초) 둡니다. 바뀜 표시를 기다리지 않고 그 자리에서 넣는 경우가 둘 있습니다.

| 바뀐 것 | 큐에 넣는 때 |
| --- | --- |
| 아이템, 골드, 스킬, 퀵슬롯, 퀘스트(줍기, 사용, 강화, 상점, 창고에 맡기기와 찾기, 제작, 퀘스트 보상), 레벨, 성향, 펫(가진 펫, 나와 있는지) | 5초 바뀜 표시. 저장 차례가 5초마다 바뀜 표시가 된 플레이어들의 사본을 한 묶음으로 넣음 |
| 위치, 체력, 마나, 경험치 | 60초 바뀜 표시. 저장 차례가 60초마다 바뀜 표시가 된 플레이어들의 사본을 한 묶음으로 넣음 |
| 아이템을 내놓는 일(떨어뜨리기, 무법자가 죽어서 떨어뜨림) | 처리하는 그 자리에서 사본 하나짜리 묶음으로 넣음 |
| 나갈 때(로그아웃, 캐릭터 선택으로 나가기, 끊김) | 캐릭터가 월드에서 빠지는 틱에 사본 하나짜리 묶음으로 넣음. 월드에 남아 있는 캐릭터([세션](#세션))는 남아 있는 동안에도 바뀜 표시의 저장을 계속함 |

- **내놓는 순서**: 인벤토리에서 빼기 → 사본을 큐에 넣기 → 바닥 개체 놓기입니다. 도중에 실패하면 아이템을 잃을 뿐 복사되지 않습니다.
- **무엇을 쓰나**: 플레이어를 쓸 때는 까닭이 무엇이든 그 플레이어의 바뀐 것 전부(캐릭터의 줄, 아이템, 골드, 스킬, 퀵슬롯, 퀘스트)를 쓰고, 사본을 넣을 때 두 바뀜 표시를 내립니다. 인벤토리 칸마다 따로 쓰면 "물약 90개를 사고 1초 뒤 1개를 떨어뜨린 틱"에 물약의 인벤토리 칸만 저장되어, 그때 서버가 죽으면 물약은 남고 골드는 깎이지 않습니다.
- **내놓는 일만 바로 넣는 까닭**: 아이템이 복사되는 것은 내놓은 쪽이 저장되지 않은 채 주운 쪽만 저장되고 서버가 죽을 때뿐입니다. 내놓은 쪽의 사본이 먼저 큐에 들어가고 큐는 들어온 순서대로 쓰이므로, 주운 쪽이 먼저 저장되는 일이 없습니다. 혼자 얻고 쓰는 변화는 늦게 써도 서버가 죽으면 잃을 뿐 복사되지 않습니다. 그래서 5초로 모아 사냥 중에 매 틱 트랜잭션이 돌지 않게 합니다.
- **읽기**: `EnterWorld`의 불러오기도 같은 큐에 넣어 저장 스레드가 읽고, 결과를 틱의 입력 큐로 돌려줍니다. 같은 큐라 그 캐릭터의 남은 사본이 다 쓰인 뒤에 읽히고, 틱은 디스크를 기다리지 않습니다. 캐릭터 목록 읽기(`CharacterList`)와 만들기(`CreateCharacter`)도 같은 큐로 저장 스레드가 합니다. 불러오는 중에 같은 캐릭터로 또 들어오면 기다리는 연결만 바꿉니다. 결과가 왔을 때 기다리던 연결이 끊겼으면 결과를 버립니다. 그 캐릭터가 월드에 남아 있으면 읽지 않고 넘겨받습니다([세션](#세션)).
- **내려갈 때와 쓰기가 실패할 때**의 규칙은 [오류와 내려가기](#오류와-내려가기)에 있습니다.
- **서버가 죽으면** 마지막으로 커밋한 묶음까지의 상태로 돌아갑니다. 5초 바뀜 표시의 것(아이템, 골드, 레벨, 성향 등)은 보통 5초 치, 60초 바뀜 표시의 것(위치, 체력, 마나, 경험치)은 60초 치까지 잃습니다. 바닥을 거친 아이템은 사라질 수는 있어도 두 곳에 남지 않습니다.

### 오류와 내려가기

- **요청 하나의 예외**: 그 플레이어만 저장하지 않고 `KICK_REASON_SERVER_ERROR`로 끊고 로그를 남깁니다(반쯤 적용된 상태일 수 있어, 전투 상태여도 월드에 남기지 않습니다).
- **내려가기**: SIGTERM을 받으면 모두에게 `KICK_REASON_SERVER_SHUTDOWN`을 보내고(있음), 접속한 모두와 월드에 남은 캐릭터([세션](#세션))의 사본을 넣고 큐를 다 쓴 뒤 끝냅니다(10초 한도).
- **쓰기 실패와 틱의 예외**: 쓰기가 실패하거나 틱에서 예외가 나면 새 사본을 만들지 않고 끝내고, systemd가 다시 띄웁니다. 앞에서부터 쓴 만큼만 남으므로 복사는 없습니다.

### 재는 것

- 10초마다 로그를 찍습니다. 틱 평균과 최대, CPU, 송신량, 할당, GC(횟수와 멈춘 시간), 틱의 차례별 시간, 패킷 종류별 수와 바이트, 보내기 큐의 길이입니다(모두 있음).
- 50 ms를 넘은 틱은 차례별 시간과 함께 따로 남깁니다. 틱이 예정보다 늦게 시작한 시간(타이머의 흔들림)과 건너뛴 틱 수도 찍습니다. 건너뛴 틱은 틱이 한 틱 넘게 늦어 타이머(`PeriodicTimer`)가 그 사이의 차례를 버린 수이고, 월드는 그만큼 틱 번호를 건너뛰어 실제 시간을 따라갑니다([과부하 때](#과부하-때)).
- 어느 함수에 시간이 드는지는 `dotnet-trace`로, 할당과 GC는 `dotnet-counters`로 봅니다.
- 최적화는 이 수치에서 큰 것부터 합니다([최적화](#최적화)).

### 과부하 때

일반적인 MMORPG처럼 한도를 미리 정해 두고, 넘어도 게임 시간은 실제 시간을 따라가게 합니다.

- **동접 상한**: 로그인한 연결 수로 세고, 정한 수를 넘는 로그인은 거절합니다(있음).
- **요청의 빈도 제한**: 연결마다의 토큰 버킷입니다([요청 검증](#요청-검증)).
- **시야 인원 상한**: 시야에 다른 플레이어가 너무 많으면(대규모 PK, 보스) 정한 수까지만 보냅니다. 한곳에 사람이 몰려도 연결 하나에 보내는 양에 끝이 있습니다.
  - 넣는 차례는 파티원 → 나를 공격하는 캐릭터(서버가 아는 대상이 나인 캐릭터) → 내 대상(서버가 아는 대상. [전투](#전투)) → 이미 받은 캐릭터(가까운 순) → 새 후보(가까운 순)입니다.
  - 1초마다 다시 고릅니다. 그 사이에 시야에 든 플레이어는 자리가 남아 있으면 그 틱에 받습니다. 이미 받은 캐릭터를 새 후보보다 먼저 두는 것은 경계에서 들어옴과 나감이 되풀이되지 않게 하려는 것입니다.
  - 다시 고르는 것은 상한 때문에 받지 못한 후보가 있는 연결뿐이고, 플레이어마다 다른 위상(개체 번호로 엇갈림)에서 해 한 틱에 몰리지 않습니다. "나를 공격하는 캐릭터"와 "내 대상"의 서버가 아는 대상은 공격 중인 대상과, 전투 상태인 동안의 마지막으로 스킬을 쓴 대상입니다(전투가 끝난 뒤의 옛 스킬 대상으로 앞에 두지 않게).
  - 몬스터와 바닥 아이템에는 상한을 두지 않습니다. 소환수는 주인과 함께 받고 함께 빠지므로([개체](#개체)의 소환수의 시야) 받는 소환수의 수는 받는 플레이어의 수를 넘지 않습니다.
  - 상한은 200입니다(한 화면 200명이 클라이언트의 목표입니다). 봇 500명을 한곳에 모아 잰 상한에서의 송신은 연결 하나에 약 11 KB/s(한 달 32 GB)라, 동접 모두가 한곳에 모여도 KVM 4에서 약 500명이어서 그대로 두었습니다([성능 수치](performance.md)).
  - 상한으로 빠진 캐릭터가 낸 사건을 어떻게 보내는지는 [전투](#전투)의 결과에, 그 캐릭터의 주변 채팅은 [사회](#사회)에 있습니다.
- **틱이 밀릴 때**: 밀린 틱을 몰아서 돌리지 않고, 틱 번호가 실제 시간을 따라 건너뜁니다(100 ms가 걸린 틱 다음은 번호가 2 오릅니다). 시스템은 지난 틱 수만큼 진행합니다. 주기로 하는 일(1초마다의 회복과 시야 인원 상한, 5틱마다의 인식, 5초와 60초의 저장)은 한 번만 하고 위상을 지킵니다. 쿨다운, 공격 간격, 이동 예산이 실제 시간 그대로라 플레이어는 느려지지 않고, 주변의 갱신만 뜸해집니다.
- 넣지 않은 것(접속 대기열, 게임 시간 늦추기, 부하에 따라 단계별로 덜어 내기)과 그 이유는 [MMO 서버 기술과 적용 여부](#mmo-서버-기술과-적용-여부)의 표에 있습니다.

### 규모를 넘으면

만들지는 않고, 한도와 나누는 차례만 적습니다.

| 차례 | 방법 | 풀리는 한도 |
| --- | --- | --- |
| 1 | 저장 스레드를 데이터베이스 캐시 서버(프로세스)로 | 게임 서버 여러 개가 같은 저장 경로를 씀 |
| 2 | 채널: 같은 필드를 도는 프로세스를 여럿 띄우고 로그인할 때 나눔 | 한 프로세스의 동접. 대신 채널이 다른 플레이어는 서로 보이지 않음 |
| 3 | 존 서버: 필드를 존으로 나눠 프로세스마다 맡기고, 앞에 연결을 쥐는 게이트웨이를 둠 | 한 필드의 동접. 존을 넘는 이동(넘겨주기)과 경계 너머의 시야(개체의 사본)가 필요함 |
| 4 | 로그인 서버를 따로 두고, 채팅과 파티를 월드 서버로 떼고, 데이터베이스를 PostgreSQL로 | 여러 게임 서버가 같은 계정과 캐릭터 데이터를 봄 |

## 월드

- **필드**: 하나이고 걸어서 이어집니다(심리스). 로딩이나 포털이 없고, 필드 전체를 틱 스레드 하나가 계산합니다. 땅은 평지이고 건물, 나무, 바위, 울타리가 길을 막습니다. 좌표와 방향의 규약은 `packets.proto`에 있습니다(1 m = 32단위, `+z`가 앞, `yaw`는 시계 방향 256단위). 쓰는 넓이는 한 변 600 m(−300 m 이상 300 m 미만. [공간](#공간)의 `FieldMap`)입니다. 끝에서 끝까지 곧게 걸어서 100초이고, 패킷의 한도(±1,024 m)보다 작습니다. 서버의 이동 검증도 패킷의 한도가 아니라 이 넓이(`Constants`의 필드의 크기)를 씁니다.
- **가장자리**: 필드의 테두리는 막힌 칸(산)으로 두릅니다. 산은 `MapObjectKinds`의 한 종류(큰 덩어리)이고 맵 원본에 놓습니다. 이동의 범위 검증(−300 m 이상 300 m 미만)은 그대로 둡니다.
- **구역**: `Zones` 테이블의 사각형입니다. 구역마다 종류(마을, 사냥터, 채집지, 보스 자리)와 안전 지대 여부, 권장 레벨이 있습니다. 서버는 개체의 위치로 구역을 구합니다. 구역이 겹치면 `Zones`의 뒤 줄이 이기고, 어느 구역에도 들지 않는 칸은 구역 0(안전 지대 아님, 이름 없음)입니다. 구역은 규칙을 가르는 이름표이고, 계산을 나누는 단위가 아닙니다.

| 구역 | 내용 |
| --- | --- |
| 마을 | 안전 지대. 부활 지점, 상점·창고·제작·퀘스트 NPC, 경비병 |
| 사냥터 1–3 | 레벨대가 다른 몬스터. 사냥터 1에는 비선공 몬스터만 있고 선공 몬스터는 사냥터 2부터 나옴(종의 나눔은 [콘텐츠의 양](#콘텐츠의-양)) |
| 채집지 | 나무, 광석, 약초. 약한 몬스터가 섞여 있음 |
| 보스 자리 | 필드 보스. 사냥터 3 안쪽 |

- **안전 지대**: 마을처럼 `Zones`에서 안전 지대로 정한 구역입니다.
  - **몬스터**: 몬스터에게는 안전 지대의 칸도 걸을 수 없는 칸이라([공간](#공간)) 들어오지 않습니다. 안에 있는 플레이어는 인식하지도 치지도 않고, 쫓던 대상이 안전 지대로 들어가면 대상을 고를 때 건너뜁니다([몬스터](#몬스터)의 누구를 칠지).
  - **지키는 것**: 플레이어끼리의 공격에서는 일반 플레이어([PK](#pk))만 지킵니다. 선공 표시가 있거나 무법자인 플레이어는 안전 지대 안에서도 맞고, 경비병도 안으로 쫓아 들어옵니다([PK](#pk)). 경계에서 치고 한 걸음 들어가 숨을 수 없습니다.
  - **안에서의 공격**: 공격자가 안전 지대 안에 있으면 공격할 수 없습니다. 대상이 선공 표시가 있거나 무법자인 플레이어일 때만 됩니다. 안전 지대 안에서 밖의 몬스터를 치지 못하게 하려는 것입니다.
- **장애물**: 길을 막는 것은 맵에 놓인 건물, 나무, 바위, 울타리와 테두리의 산입니다. 건물은 들어갈 수 없는 덩어리이고 건물 안, 계단, 다리는 없습니다. 울타리도 다른 것처럼 걷기와 선을 함께 막습니다(걷지는 못하지만 마법은 지나가는 칸은 두지 않습니다. [범위 밖](#범위-밖)). `MapObjectKinds`의 "막는지"는 막지 않는 장식(풀, 꽃)도 놓을 수 있다는 뜻입니다. 막는 것이 차지하는 1 m 칸이 막힌 칸이 되고, 이동, 몬스터, 공격, 발사체, 자동 사냥이 모두 이 칸을 봅니다. 칸을 읽는 규칙은 [공간](#공간)에 있습니다.
- **맵 원본**: 둘입니다. 종류의 표는 `data/`의 xlsx에 있는 `MapObjectKinds`입니다([데이터 테이블](#데이터-테이블)). 놓인 것의 원본은 `data/`의 텍스트 파일이고, 탭으로 나눈 줄 하나가 놓인 것 하나의 종류, 위치(미터, 정수), 방향(0·90·180·270도)입니다. 위치는 방향대로 돌린 뒤 차지하는 사각형의 작은 모서리입니다(홀수 크기도 정수 미터에 놓이게). 맵 생성기(`mmo/tools/map/`)가 이것을 1 m 칸의 격자로 폅니다. 게임의 테이블과 규칙을 아는 코드라 data-tool이 아니라 mmo에 두고, data-tool의 워크북 읽기(`readTables`)와 해시(`dataHash`)를 가져다 씁니다(2026-11-13 정함). 격자는 생성물이라 손으로 고치지 않습니다. 엔진마다 맵을 따로 만들면 한쪽에서 벽인 곳을 다른 쪽 플레이어가 지나가므로, 서버와 두 엔진이 한 원본에서 나온 것을 읽습니다.
  - **툴이 내는 것**: 격자 바이너리(서버와 두 클라이언트가 읽음), 놓인 것의 목록(종류의 줄 포함. 두 엔진의 에디터 도구가 읽음), 미리 보기 그림 한 장(SVG. 구역, 막힌 칸, 스폰, NPC, 채집물, 부활 지점).
  - **툴의 검증**: 어긋나면 생성하지 않습니다. 스폰, NPC, 채집물, 부활 지점, 무법자의 부활 지점이 막힌 칸 위에 있지 않아야 하고, 그 자리들이 마을의 부활 지점에서 걸어서 닿아야 하고, 몬스터 무리의 자리가 안전 지대 밖이어야 하고, 무법자의 부활 지점이 경비병의 인식 범위 밖이어야 하고, 놓인 것이 필드 밖으로 나가지 않아야 합니다.
  - **해시**: 격자와 목록은 데이터 해시에 듭니다([구조 원칙](#구조-원칙)).
  - **레벨 에셋**: Unreal 에디터에서 격자에 맞춰 놓고 에디터 도구로 내보내 원본의 텍스트 파일을 만듭니다. 레벨 에셋은 그 파일에서 언제든 다시 만들 수 있습니다(메시와 충돌은 에디터 도구가 놓인 것의 목록에서 놓습니다). 레벨 에셋이 낡았는지는 한 가지로 봅니다. 패키징할 때 에디터 도구가 레벨 에셋에서 놓인 줄(종류, 위치, 방향)과 그 종류의 줄 전체(가로·세로, 막는지, 카메라를 막는지, 메시의 키)를 다시 내보내고, 이것이 툴이 낸 놓인 것의 목록(놓인 줄과, 놓인 것이 쓰는 종류의 줄)과 같은지 봅니다. 한 번도 놓이지 않은 종류의 줄은 견주지 않습니다. 다르면 멈춥니다(파일만 바뀐 것, 레벨 에셋만 바뀐 것, 놓인 종류의 줄만 바뀐 것을 함께 잡습니다). Unity의 씬도 에디터 도구가 같은 목록에서 만듭니다. 환경 메시의 원본은 두 엔진이 함께 읽는 `mmo/art/`에 둡니다.

## 개체

| 종류 | 움직임 | 체력 | 고를 수 있는 행동 |
| --- | --- | --- | --- |
| 플레이어 | 클라이언트가 보냄 | 있음 | 공격(PK), 파티 초대, 귓속말 |
| 몬스터 | 서버가 계산 | 있음 | 공격 |
| NPC | 없음(경비병은 서버가 계산) | 없음 | 상점, 창고, 제작, 퀘스트 |
| 채집물 | 없음 | 없음(남은 횟수) | 채집 |
| 바닥 아이템 | 없음 | 없음 | 줍기 |
| 소환수 | 서버가 계산 | 있음 | 공격(남의 소환수. 플레이어처럼 강제 공격을 켜야 함) |

- **`EntityEnter`가 싣는 것**: 시야에 들어온 개체마다 종류에 따라 아래를 싣습니다. 템플릿 번호는 몬스터, 소환수, NPC, 채집물의 테이블 행입니다.

| 종류 | 싣는 것 |
| --- | --- |
| 모두 | 번호, 종류, 위치와 방향 |
| 플레이어 | 이름, 직업, 레벨, 체력과 최대 체력, 이름 색(일반, 선공, 무법자), 입은 무기, 나와 있는 펫(`Pets`의 줄. 없으면 0), 걸린 효과, 진행 중인 일(종류, 번호, 끝나는 틱. `Progress`와 같은 필드), 죽었는지, 움직이는 중이면 방향과 속도 |
| 몬스터 | 템플릿 번호, 체력과 최대 체력, 걸린 효과, 죽었는지, 움직이는 중이면 다음 꺾이는 점과 속도 |
| NPC, 채집물 | 템플릿 번호. 경비병은 움직이는 중이면 몬스터처럼 다음 꺾이는 점과 속도 |
| 바닥 아이템 | 아이템 번호, 수량, 강화 수치, 주인(플레이어 번호나 파티 번호 가운데 하나. 주인이 없으면 비움), 주인만 줍는 시간이 끝나는 틱, 플레이어가 떨어뜨렸는지 |
| 소환수 | 템플릿 번호(`Monsters`의 줄), 주인(플레이어 번호), 사라지는 틱, 체력과 최대 체력, 걸린 효과, 죽었는지, 움직이는 중이면 몬스터처럼 다음 꺾이는 점과 속도 |

- **표시 상태**: 보이는 동안 바뀌는 겉모습이고 이름 색, 입은 무기, 레벨, 나와 있는 펫 넷입니다. 하나라도 바뀌면 표시 상태 변화 패킷(`EntityState`)이 그 개체를 받은 연결과 본인에게 알리고, 이 패킷은 넷을 늘 함께 싣습니다. 죽음과 부활은 `EntityState`에 싣지 않고 전투의 사건이 알립니다([전투](#전투)의 결과). 기절과 감속은 표시 상태가 아니라 효과 목록에서 그리고(머리 위 아이콘), 채집 중과 제작 중은 진행 중인 일로 알립니다([전투](#전투)).
- 겉모습은 무기만 바꿉니다. 방어구를 입어도 캐릭터의 모습은 그대로입니다([범위 밖](#범위-밖)).
- 시야에 들어오고 나가는 개체는 0.3초 동안 서서히 나타나고 사라집니다.
- 시야에 보낼 다른 플레이어의 수에는 상한이 있습니다([과부하 때](#과부하-때)의 시야 인원 상한).
- **소환수의 시야**: 소환수는 시야에서 주인을 따릅니다. 주인을 받은 연결이 소환수도 받고, 주인이 나갈 때 함께 나갑니다. 주인 본인은 늘 받습니다. 소환수의 자리로 시야를 따로 구하지 않습니다(주인 둘레 20 m 안에 있습니다). 소환수가 공격자인 사건은 다른 사건처럼 대상을 받은 연결에 가고, 소환수를 받지 않은 연결에는 번호 0으로 갑니다([전투](#전투)의 결과).

## 캐릭터와 능력치

- 계정(로그인 ID) 하나에 캐릭터 4개까지입니다(`Constant`). 이름은 한글·영문·숫자 2–12자이고 서버 전체에서 하나입니다(영문은 대소문자를 가리지 않고 같은 이름으로 봅니다). 머리 위에 이 이름이 보이고, 로그인 ID는 보이지 않습니다.
- 직업은 둘입니다. **기사**는 근접(사거리 2 m)이고 체력과 방어력이 높습니다. **마법사**는 원거리 마법(사거리 12 m)이고 마나와 공격력이 높고 체력이 낮습니다. 직업은 만들 때 정하고 바꿀 수 없습니다. 클라이언트는 `EntityEnter`의 직업으로 그림을 고릅니다([개체](#개체)).
- 직업마다 다른 수치는 `Classes`와 `Levels`에 있습니다([데이터 테이블](#데이터-테이블)). 무기와 스킬은 직업마다 다르고 방어구는 두 직업이 함께 씁니다([아이템](#아이템), [전투](#전투)).
- 능력치는 넷입니다: **최대 체력, 최대 마나, 공격력, 방어력**. 이동 속도는 모두 같고(6 m/s, `Constant`의 값) 감속 효과만 줄입니다.
- 능력치 = 레벨의 기본값(`Levels`) + 입은 장비와 강화 + 걸린 효과. 서버가 바뀔 때마다 다시 더하고, 클라이언트에는 결과를 보냅니다.
- 체력과 마나는 시간이 지나면 차오릅니다. 전투 상태([전투](#전투))가 아닐 때는 초당 최대 체력·마나의 5%, 전투 상태에서는 1%입니다. 죽은 개체는 회복하지 않습니다(몬스터의 회복은 [몬스터](#몬스터)). 물약은 바로 채우고 쿨다운이 있습니다. 물약의 쿨다운은 쓰는 종류(체력 회복, 마나 회복)마다 하나입니다(단계가 다른 물약을 번갈아 써서 피하지 못하게). 쿨다운의 길이는 쓴 물약의 `Items` 값입니다.

## 전투

- **대상**: 개체 하나를 대상으로 고릅니다. 고르는 것은 클라이언트 안의 일이라 서버에 알리지 않습니다(패킷 없음). 서버가 아는 내 대상은 공격 중인 대상(`AttackStart`)과 마지막으로 스킬을 쓴 대상뿐입니다. 고르고 푸는 조작은 [화면](#화면)의 조작 표에, 다른 플레이어를 공격하는 조건은 [PK](#pk)의 강제 공격에 있습니다.
- **시작과 타격**: 동작이 시작하는 때와 맞는 때를 서버가 따로 알립니다. 서버는 공격이나 스킬을 시작한 틱에 시작 사건(`AttackSwing`, `SkillUsed`)을 보내고, 결과(피해, 효과)는 "타격까지의 시간" 뒤에 적용합니다. 데이터에는 밀리초로 두고 읽을 때 틱 수로 바꿉니다([구조 원칙](#구조-원칙)). 타격까지의 시간은 기본 공격, 몬스터의 공격, 스킬마다 데이터의 값입니다(기본 공격의 처음 값 300 ms = 6틱. 동작에서 무기가 닿는 순간에 맞춥니다. 0이면 같은 틱). 클라이언트가 받은 순서대로 그리면 무기가 닿는 순간에 피해 숫자가 뜹니다. 타격할 틱에 다음 가운데 하나면 결과를 적용하지 않습니다: 대상이 죽었음, 대상이 월드에서 빠졌음, `CanAttack`([PK](#pk))이 거짓이 됨(안전 지대에 들어감, 파티원이 됨), 대상이 복귀 중인 몬스터임, 공격자가 그 사이에 죽었거나 기절했거나 월드에서 빠졌음. 대상이 사거리 밖으로 나간 것은 맞습니다. 기본 공격과 스킬이 같고, 이미 뺀 비용은 돌려주지 않습니다. 공격을 멈춰도 이미 시작한 타격은 맞습니다.
  - **고른 이유**: 클라이언트가 `Damaged`를 받고 숫자만 늦게 띄우는 방법은 패킷이 늘지 않습니다. 하지만 체력 바, 죽음, 내 체력처럼 따라오는 결과를 모두 같은 만큼 늦춰야 해서 화면 코드 곳곳에 지연이 퍼집니다. 서버가 시간을 가지면 패킷이 순서대로 오므로 클라이언트는 받은 대로 그립니다.
  - **드는 것**: 공격 한 번에 `AttackSwing` 하나(약 8바이트, 계산한 값)입니다. 둘레에서 20명이 초당 한 번씩 치면 받는 쪽마다 약 160 B/s이고, 이동만의 송신량(15,354 B/s)의 약 1%입니다(재지 않았습니다).
- **기본 공격**: 클라이언트는 공격 시작(`AttackStart`, 대상)과 멈춤만 보냅니다. 서버는 공격 시작을 받은 입력 차례에 대상이 있고 살아 있고 그 연결이 받은 개체인지, `CanAttack`, 복귀 중인 몬스터가 아닌지를 보고, 어긋나면 실패로 답합니다. 통과한 뒤에는 다음 공격 틱마다 대상이 살아 있고 사거리 안이고 선이 트여 있는지([공간](#공간))와 `CanAttack`([PK](#pk))을 보고, 통과하면 그 틱에 `AttackSwing`(공격자, 대상)을 보냅니다. 타격하는 틱에 피해를 주고 `Damaged`를 보냅니다(위의 시작과 타격). 다음 공격 틱은 시작한 틱에서 공격 간격만큼 뒤이고, 공격을 멈춰도 남습니다(껐다 켜서 빨리 치지 못하게). 서버의 공격 상태가 끝나는 때는 대상의 죽음, 대상이 월드에서 빠짐, `CanAttack`이 거짓이 됨(실패 알림을 보냅니다), 대상인 몬스터가 복귀를 시작함(실패 알림을 보냅니다. 이유는 "공격할 수 없는 대상"이고, 복귀 중인 몬스터에게 보낸 공격 시작도 같은 이유로 실패합니다), 공격 멈춤 요청, 공격자의 죽음, 공격자의 연결이 떨어짐([세션](#세션))입니다. 기절한 동안은 끝나지 않고 쉽니다. 사거리 안이어도 벽에 막혔으면 사거리 밖과 같이 시작하지 않고 기다립니다. 서버는 이동과 공격을 따로 보므로, 걷는 중에도 사거리 안이면 기본 공격이 시작합니다. 대상에게 다가가는 것은 클라이언트의 이동이고, 걸어갈 곳은 사거리 안이면서 선이 트인 곳입니다(대상이 몬스터면 안전 지대 밖이어야 합니다. 안에서는 몬스터를 치지 못합니다. [월드](#월드)의 안전 지대). 패킷이 줄고, 공격 속도를 속일 수 없습니다.
- **스킬**: 클라이언트는 `UseSkill`에 스킬 번호, 대상(또는 자기), 강제 공격 표시를 실어 보냅니다(서버가 그 표시를 보는 스킬은 [PK](#pk)의 강제 공격). 직선으로 나는 스킬은 대상 없이도 쓸 수 있습니다. 서버는 요청을 받은 입력 차례에 상태(살아 있음, 기절 아님, 진행 중인 일 없음), 배웠는지, 쿨다운, 마나, 대상(피해나 상태 이상을 주는 스킬만: 있고 살아 있고 받은 개체인지, `CanAttack`, 복귀 중인 몬스터가 아닌지. 중심이 자기인 스킬과 직선으로 나는 스킬은 대상을 보지 않습니다), 사거리와 선을 차례대로 확인합니다. 대상에게 피해나 상태 이상을 주는 스킬은 대상이 복귀 중인 몬스터면 공격 시작과 같이 "공격할 수 없는 대상"으로 실패하고 비용을 빼지 않습니다(대상을 보지 않는 직선 스킬과 중심이 자기인 스킬은 해당하지 않습니다). 사거리 안인데 선이 막혔으면 `FailReason`의 "막힘"으로 실패합니다. 직선으로 나는 스킬은 사거리와 선을 미리 보지 않고 쏩니다(벽에 닿으면 발사체가 사라집니다). 발동은 전투 차례에서 합니다([틱의 차례](#틱의-차례)).
  - **시전 시간이 없는 스킬**: 확인한 자리에서 비용(마나, 쿨다운)을 빼고, 그 틱에 `SkillUsed`(시전자, 스킬, 대상)를 보냅니다. 결과는 타격까지의 시간 뒤에 적용합니다.
  - **시전 시간이 있는 스킬**: 시전은 진행 중인 일입니다(아래). 시전 시간의 틱 수 뒤에 발동하며 비용도 그때 뺍니다. 발동하는 틱에 `SkillUsed`와 결과를 함께 냅니다(타격까지의 시간은 0으로 둡니다). 직선으로 나는 스킬은 발동할 때 사거리와 선을 다시 보지 않습니다.
  - **회복과 강화의 대상**: 자기나 파티원에게 씁니다. 대상이 파티원이 아니면(소환수도) 자기에게 씁니다. 사거리와 선은 파티원에게 쓸 때만 봅니다(자기에게 쓰면 보지 않습니다).

- **진행 중인 일**: 시전, 채집, 제작([생활](#생활)), 귀환([아이템](#아이템))을 묶은 것이고 규칙이 같습니다.
  - 한 개체가 한 번에 하나만 합니다. 진행 중에는 다른 스킬, 아이템 사용, 공격 시작, 채집·제작·귀환의 시작 요청이 실패합니다. 이미 켜 둔 기본 공격은 진행 중에 쉬고 끝나면 이어집니다.
  - 취소되는 때는 죽음, 기절, 시작한 자리에서 벗어남(방향만 바꾼 것은 아닙니다), 연결이 끊기거나 월드에서 나감, 채집하던 채집물이 사라짐([생활](#생활))입니다. 채집, 제작, 귀환은 피해를 받아도 취소되고, 시전은 피해로는 취소되지 않습니다. 시전 시간이 있는 스킬은 보낼 때 내 캐릭터가 걷고 있으면(스킬을 누른 때, 대상에게 다가간 뒤, 자동 사냥이 쓸 때 모두) 클라이언트가 캐릭터를 세우고(걷던 경로는 버립니다) 위치를 보낸 뒤에 요청을 보내고, 누를 때 쥐고 있던 이동 입력은 이동 입력이 한 번 없어질 때까지 무시합니다(바로 취소되지 않게).
  - 끝나는 틱에 요청 때의 확인을 모두 다시 봅니다(대상이 살아 있는지와 복귀 중이 아닌지, `CanAttack`, 사거리, 선, 마나, 재료, 인벤토리의 자리). 통과하지 못하면 아무것도 빼지 않고 `ProgressCancelled`(이유)를 보냅니다. 성공은 따로 알리지 않습니다. 받은 쪽은 `Progress`의 끝나는 틱이 지나면 동작을 끝내고, 결과는 그 일의 패킷이 알립니다(스킬은 `SkillUsed`, 채집과 제작은 본인의 인벤토리 변화, 귀환은 순간 이동).
  - 패킷은 한 쌍입니다. `Progress`(개체, 종류, 번호, 끝나는 틱)와 `ProgressCancelled`(개체, 이유)이고(이유는 `FailReason`입니다. 끝나는 틱의 확인에서 걸렸으면 요청 때의 실패와 같은 값, 중간에 취소됐으면 "취소됨"), 번호는 종류에 따라 그 테이블의 번호입니다(시전은 `Skills`, 채집은 `GatherNodes`, 제작은 `Recipes`, 귀환은 `Items`). 개체를 받은 연결 모두와 본인에게 갑니다. 클라이언트는 종류에 맞는 동작과 진행 바를 그립니다(남의 채집과 제작도 보입니다). 종류마다의 패킷은 두지 않습니다. 내 것이 "취소됨"이 아닌 이유로 취소되면 실패한 요청처럼 그 이유를 알림으로 띄웁니다([화면](#화면)).
- **적**: 범위 스킬과 직선으로 나는 스킬이 맞히는 것은 `CanAttack`([PK](#pk))을 통과한 몬스터와, 강제 공격을 켜고 쓴 경우의 플레이어와 남의 소환수입니다([PK](#pk)의 강제 공격. 시전자가 안전 지대 안이면 몬스터는 맞지 않습니다. [월드](#월드)의 안전 지대). 범위 스킬도 직선으로 나는 스킬처럼 복귀 중인 몬스터와 죽은 개체는 맞히지 않습니다(피해도 효과도 주지 않고 피해 표에 넣지 않습니다). 직선으로 나는 스킬은 대상을 실어 보내도 단일 대상 스킬이 아닙니다. 강제 공격 표시, 선공 표시가 붙는 틱, 소환수의 대상에서 범위 스킬과 같이 다룹니다.
- **발사체**: 대상을 따라가는 것과 직선으로 나는 것 둘입니다. 속도는 데이터의 값입니다([데이터 테이블](#데이터-테이블)).
  - **대상을 따라가는 것**(마법사의 기본 공격, 원거리 몬스터의 공격. [몬스터](#몬스터)): 서버가 개체로 옮기지 않습니다. 시작한 틱에 사거리와 선을 보고(위의 기본 공격), 타격하는 틱을 "타격까지의 시간 + 거리 ÷ 발사체의 속도"로 정해 그 틱에 결과를 적용합니다. 날아가는 동안에는 선을 다시 보지 않고, 결과를 적용하지 않는 경우는 위의 시작과 타격과 같습니다. 클라이언트는 `AttackSwing`을 받아 타격까지의 시간이 지난 뒤 발사체를 대상 쪽으로 그립니다.
  - **직선으로 나는 것**(마법사의 첫째 스킬 하나): 서버가 옮깁니다. `SkillUsed` 뒤 타격까지의 시간이 지난 틱에 나가, 쏜 방향으로 사거리만큼 날아가 경로에서 처음 닿는 적에게 맞고 사라집니다. 비켜서 피하고 벽에 막히는 것이 보입니다. 닿았는지는 틱마다 그 틱에 옮긴 경로(선분)와 개체의 원으로 봅니다(반지름은 데이터의 값). 그 선분이 벽에 닿으면 그 자리에서 사라집니다. 복귀 중인 몬스터와 죽은 개체는 지나갑니다. 날아가는 동안 쏜 쪽이 죽거나 기절하거나 월드에서 빠지면 사라집니다. 발사체가 나가기 전(타격까지의 시간 사이)에 그렇게 되면 발사체는 나가지 않습니다.
  - **직선의 방향**: `UseSkill`에 방향을 싣지 않고, 발사체가 나가는 틱에 서버가 정해 `yaw`(256단위)로 나타냅니다. 대상이 있으면 대상 쪽이고, 대상 없이 썼거나 실려 온 대상이 죽었거나 없으면 캐릭터가 보는 쪽입니다. 끌어서 조준하는 것은 넣지 않습니다([범위 밖](#범위-밖)).
  - **직선으로 나는 것의 사건**: 발사체는 개체가 아니어서 시야 목록에 넣지 않습니다. 발사체가 나간 틱에 발사체 사건(쏜 쪽, 나간 자리와 틱, 방향, 속도, 번호)을, 맞거나 사라진 틱에 그 번호의 끝을 쏜 쪽을 받은 연결과 쏜 본인에게 보내고, 클라이언트는 그 사이를 그립니다. 나간 자리와 틱을 싣는 것은 클라이언트가 서버와 같은 경로를 그리게 하려는 것입니다. 쏜 쪽을 받지 않은 연결에는 보내지 않습니다(쏜 쪽이 보이지 않으면 발사체도 그리지 않습니다). 이 스킬의 `SkillUsed`도 대상이 실려 있든 아니든 발사체 사건과 같이 쏜 쪽을 받은 연결과 쏜 본인에게 보냅니다(실려 온 대상은 방향에만 쓰고 쏜 쪽이 받지 않은 개체일 수도 있어서, 대상을 받은 연결로 보내면 쏜 본인이 받지 못할 수 있습니다). 실린 대상의 번호는 받는 연결이 그 대상을 받지 않았어도 그대로 싣고, 받은 쪽이 그 대상을 받지 않았으면 쏜 쪽을 대상 쪽으로 돌려 그리지 않습니다. 맞은 결과(`Damaged`)는 따로 오고 아래 결과의 규칙을 따릅니다.
- **효과**: 강화와 상태 이상은 `Effects`의 행 하나이고, 개체에 "효과 번호, 끝나는 틱"으로 붙습니다. 같은 효과는 시간만 새로 합니다. 끝나는 틱에 서버가 효과를 떼고 능력치를 다시 구합니다([예약한 일](#예약한-일)). 감속이 걸리면 서버의 이동 예산도 그만큼 줄고, 기절한 동안의 `Move`는 되돌립니다. 클라이언트도 내게 걸린 감속과 기절을 이동과 입력에 반영해 되돌려지지 않게 합니다. 기절한 동안에도 대상이 풀리거나 바뀌면 [화면](#화면)의 조작 표대로 공격 멈춤을 보냅니다(서버가 받는 것은 [요청 검증](#요청-검증)).
- **전투 상태**: 공격을 시작했거나 피해나 상태 이상을 받은 틱부터 5초 동안입니다(피해 없이 기절이나 감속만 맞아도 전투 상태가 됩니다). 공격을 시작한 틱은 기본 공격은 `AttackSwing`을 낸 틱, 피해나 상태 이상을 주는 스킬은 `SkillUsed`를 낸 틱입니다(사거리 밖에서 보낸 `AttackStart`만으로는 붙지 않습니다). 피해나 상태 이상을 주는 스킬 가운데 시전 시간이 있는 것은 시전을 시작한 틱(`Progress`를 낸 틱)에도 붙습니다. 회복, 강화, 소환 스킬은 전투 상태를 만들지 않습니다. 소환수가 공격을 시작한 틱에는 주인에게 전투 상태가 붙습니다([몬스터](#몬스터)의 소환수).
- **피해**: 처음 식은 `피해 = max(1, (공격력 × 계수 − 방어력 × 0.5) × 난수(0.9–1.1))`입니다. 소수는 버립니다(최소 1은 그대로입니다). 기본 공격의 계수는 1이고 몬스터도 같은 식을 씁니다. 공식은 formula-tool로 만들어 서버가 계산합니다. 치명타는 `Constants`의 확률로 나고 피해에 `Constants`의 배수를 곱합니다(처음 값 5%, 1.5배). `Damaged`에 치명타 표시를 싣고 클라이언트는 큰 숫자로 그립니다. 회복 스킬이 채우는 양은 시전자의 공격력 × 계수입니다. 명중과 회피는 넣지 않습니다.
- **결과**: 서버는 공격 동작의 시작(`AttackSwing`: 누가, 누구에게), 스킬 사용(`SkillUsed`: 누가, 무엇을, 누구에게), 피해(`Damaged`: 누가 얼마, 남은 체력, 치명타 표시), 효과가 붙음, 죽음, 부활을 사건으로 보냅니다.
  - **누구에게**: 사건의 대상(공격과 스킬의 대상, 맞은 쪽, 효과가 붙은 쪽, 죽은 쪽. 대상이 없으면 행위자)을 받은 연결 모두와 대상 자신입니다. 직선으로 나는 스킬의 `SkillUsed`만 다릅니다(위의 직선으로 나는 것의 사건). 개체를 "받은 연결"은 그 개체의 `EntitiesEnter`를 받고 아직 `EntitiesLeave`를 받지 않은 연결입니다.
  - **번호 0**: 그 연결이 받지 않은 다른 쪽(시야 인원 상한으로 빠진 공격자나 시전자)의 번호는 0으로 싣습니다. 시작 사건(`AttackSwing`, `SkillUsed`)도 같습니다. 직선으로 나는 스킬의 `SkillUsed`에 실린 대상만은 0으로 바꾸지 않습니다(위의 직선으로 나는 것의 사건). 클라이언트는 번호가 0이면 개체를 찾지 않고 대상 쪽의 결과(체력, 피해 숫자, 피격 반응)만 반영합니다.
  - **효과가 떨어짐**: 따로 알리지 않습니다. 붙을 때 끝나는 틱을 함께 알리므로 클라이언트가 그 틱이 지나면 지웁니다. 시간이 다 되기 전에 떼이는 것은 죽을 때뿐이고, 클라이언트가 죽음 사건을 받으면 그 개체의 효과를 비웁니다.
  - **나에게만**: 내 상태(체력과 마나, 전투 상태가 끝나는 틱, 선공 표시가 끝나는 틱)는 한 패킷에 실어 바뀐 틱에 보냅니다. 쿨다운은 월드에 들어올 때(`EnterWorldResult` 뒤에) 전체를, 그 뒤에는 바뀐 것을 보냅니다(물약 포함).
  - **1초마다**: 피해가 아닌 까닭으로 체력이 바뀐 개체(자연 회복, 물약, 회복 스킬, 복귀 중인 몬스터)는 1초마다 모아 체력과 최대 체력을 보냅니다.
  - **새로 들어온 개체**: 걸려 있는 효과와 진행 중인 일은 `EntityEnter`가 싣습니다([개체](#개체)).
- **클라이언트의 예측**: 쿨다운 표시와 내 동작의 시작(첫 기본 공격, 스킬)만 미리 보여 줍니다. 내 스킬의 동작은 요청을 보낼 때 미리 시작하고 실패가 오면 끊습니다. 공격 동작은 다른 개체와 내 캐릭터 모두 `AttackSwing`이 올 때 시작합니다. 내 첫 공격만 `AttackStart`를 보낼 때 미리 시작하고, 그 공격의 `AttackSwing`이 오면 다시 시작하지 않습니다. 피해 숫자와 피격 반응은 서버의 결과(`Damaged`)가 올 때만 보여 줍니다. 쿨다운 규칙은 서버가 만든 비교 벡터로 두 클라이언트를 검사합니다.
- **클라이언트의 동작과 방향**: 걷는 중의 공격은 하체는 이동, 상체는 공격·스킬 동작으로 섞어 그립니다. 공격이나 스킬 동작을 시작할 때 그 개체를 대상 쪽으로 돌려 그립니다(그리기만 하고 서버의 `yaw`는 그대로입니다). 대상이 없거나, 내가 받지 않은 개체이거나, 행위자의 번호가 0이면 돌리지 않습니다. 맞은 개체는 0.1초 번쩍이고, 내가 맞으면 카메라가 약하게 흔들립니다(설정에서 끕니다).

## 몬스터

- **테이블**: 몬스터의 수치는 `Monsters`에, 놓는 자리는 `Spawns`에 있습니다([데이터 테이블](#데이터-테이블)). `Spawns`의 줄 하나가 한 무리이고, 그 줄이 가진 점이 "무리의 자리"입니다. 서버는 뜰 때 무리의 자리에서 흩는 반경 안의, 무리의 자리에서 몬스터가 곧게 걸어갈 수 있는 점(`CanWalkLine`. [공간](#공간))을 수만큼 골라 개체를 하나씩 놓습니다. 그 점이 그 개체의 "놓인 점"입니다. 채집물을 흩을 때는 플레이어 쪽의 걷는 선을 씁니다. 추적 한계, 복귀, 배회, 리스폰은 놓인 점이 기준입니다. 무리의 자리가 지켜야 하는 것(걸을 수 있는 칸, 몬스터 무리는 안전 지대 밖)은 [월드](#월드)의 맵 원본 검증에 있습니다. 다시 나오는 시간은 몬스터와 채집물 모두 `Spawns`에만 둡니다.
- **원거리 몬스터**: 사냥터 2의 선공 몬스터 한 종은 원거리 공격을 합니다. 공격 사거리가 길고 대상을 따라가는 발사체를 쏩니다(마법사의 기본 공격과 같습니다. [전투](#전투)의 발사체).
- **상태**: 대기(놓인 점 근처를 배회) → 추적 → 공격 → 복귀. 선공 몬스터는 인식한 플레이어를, 비선공은 자기를 때린 플레이어를 추적합니다. 놓인 점에서 추적 한계보다 멀어지면 복귀하고, 복귀하는 동안은 피해를 받지 않고 초당 최대 체력의 20%가 찹니다(처음 값). 몬스터는 자연 회복이 없어 체력은 복귀하는 동안에만 찹니다. 추적 한계는 놓인 점에서의 직선거리로 봅니다(길의 길이가 아닙니다).
- **인식**: 선공 몬스터는 5틱마다 인식 범위 안의 플레이어 가운데 안전 지대 밖에 있고 선이 트인(`HasLine`. [공간](#공간)) 플레이어만 인식합니다. 몬스터는 개체 번호를 5로 나눈 나머지가 같은 틱에 인식합니다(한 틱에 몰리지 않게). 맞아서 시작하는 추적은 선과 상관없습니다.
- **피해 표**: 몬스터마다 플레이어가 준 피해의 합을 플레이어마다 쌓습니다(소환수가 준 피해는 소환수의 줄에 따로 쌓고, 견줄 때는 주인의 편에 합칩니다. 아래의 소환수). 인식한 플레이어는 피해 0으로 표에 듭니다. 상태 이상만 건 스킬도 때린 것이라, 건 플레이어가 피해 0으로 표에 들고 비선공 몬스터도 그 플레이어를 쫓습니다. 대상과 드롭의 주인을 고를 때는 그 순간의 파티로 합쳐 견주고, 피해의 합이 같으면 먼저 든 쪽이 이깁니다. 먼저 든 쪽은 그 편의 줄 가운데 가장 먼저 든 줄로 견줍니다(인식된 틱이나 처음 때린 틱이 이른 쪽이고, 같은 틱이면 그 틱 안에서 먼저 든 줄). 복귀를 시작하면 표를 비우고, 죽거나 월드에서 빠진 플레이어는 표에서 뺍니다.
- **누구를 칠지**: 피해 표에서 합이 가장 큰 쪽입니다. 파티로 합쳐 고른 대상 가운데서는 그 편(파티와 그 소환수)에서 피해가 가장 큰 플레이어나 소환수를 칩니다. 편 안에서 피해가 같으면 먼저 든 줄(든 틱이 이른 쪽, 같은 틱이면 먼저 든 줄)을 칩니다. "닿을 수 없음"으로 표시한 플레이어는 그 5초 동안 건너뜁니다. 안전 지대로 들어간 플레이어는 피해 표에서 지우지 않고 대상을 고를 때만 건너뜁니다(경험치와 드롭의 주인을 정할 때는 표에 남아 있습니다). 건너뛰는 것은 개체마다이고 편의 합에는 그 줄의 피해도 넣습니다. 고른 편에서 건너뛰는 개체를 빼고 다음으로 피해가 큰 플레이어나 소환수를 치고, 그 편에 칠 것이 없으면 다음으로 합이 큰 편에서 고릅니다. 피해 표의 대상이 모두 닿을 수 없거나 안전 지대 안이어서 고를 대상이 없으면 복귀합니다.
- **누가 잡았는지**: 죽는 순간 피해 표에서 합이 가장 큰 플레이어나 파티가 경험치를 받고 드롭의 주인이 됩니다([아이템](#아이템)의 드롭). 보스도 같습니다.
- **추적**: 대상까지 곧게 걸어갈 수 있으면(`CanWalkLine`) 곧게 갑니다. 아니면 A*로 길을 찾고, 대상이 3 m 넘게 옮기기 전에는 그 길을 따라갑니다. 길은 놓인 점에서 추적 한계 안의 칸에서만 찾아, 한 번의 길찾기가 보는 칸 수에 끝이 있습니다. 그 안에 길이 없으면 그 대상을 5초 동안 건너뜁니다(피해 표에서 빼지 않고 "닿을 수 없음"으로 표시합니다). 고를 대상이 남지 않으면 복귀합니다(위의 누구를 칠지).
- **복귀**: 놓인 점까지 곧게 걸어갈 수 있으면 곧게, 아니면 A*로 갑니다. 이때 A*가 살피는 범위는 놓인 점에서 "지금 거리 + 4 m" 안의 칸입니다. 추적 한계를 막 넘은 출발 칸이 범위 밖이 되지 않게 하려는 것입니다. 길이 없으면 놓인 점으로 순간 이동합니다. 복귀하는 동안은 피해를 받지 않으므로 악용할 수 없습니다.
- **배회**: 대기 상태에서 놓인 점에서 배회 반경 안이고 지금 서 있는 곳에서 곧게 걸어갈 수 있는 무작위 점으로 걷고, 3–6초 서 있다가 다음 점으로 갑니다(처음 값). 그런 점만 고르므로 길찾기가 필요 없습니다. 둘레 9개의 시야 칸에 플레이어가 없는 몬스터는 계산하지 않으므로([틱의 차례](#틱의-차례)) 배회도 하지 않습니다.
- **안전 지대**: 들어가지 않고, 안의 플레이어를 인식하지도 치지도 않습니다([월드](#월드)의 안전 지대).
- **죽은 뒤**: 죽은 몬스터는 죽은 채로 3초 동안 남아 쓰러지는 모습을 보인 뒤 사라집니다. 죽는 틱에 바로 빼면 클라이언트가 이미 없는 개체의 피해와 죽음을 받습니다. 다시 나오는 시간은 사라진 틱이 아니라 죽은 틱부터 셉니다.
- **이동**: 경로의 다음 꺾이는 점과 속도를 알립니다([공간](#공간)의 이동 알림).
- **필드 보스**: `Monsters`의 종류가 보스이고 `Spawns`의 다시 나오는 시간이 긴 몬스터입니다(처음 값 10분. 시연에서 기다려 볼 수 있는 길이입니다). 일정 간격으로 범위 공격을 합니다. 범위 공격은 `Skills`의 줄이고(간격은 그 줄의 쿨다운입니다), 바닥에 범위를 먼저 알리고 예고 시간(처음 값 1.5초) 뒤에 피해를 주어 걸어서 나가거나 벽 뒤에 숨어 피할 수 있습니다([공간](#공간)). 범위의 중심은 예고하는 틱의 대상 자리에 고정합니다. 예고 뒤에 보스가 죽거나 복귀를 시작하면 피해를 주지 않습니다. 예고 뒤에 시야에 들어온 연결은 예고를 받지 못합니다(받아들입니다). 보스는 기절과 감속에 걸리지 않습니다. 드롭과 경험치는 일반 몬스터와 같이 받습니다(위의 누가 잡았는지). 보스가 나오면 필드 전체에 자리(보스의 놓인 점)와 함께 알리고, 죽어도 필드 전체에 알립니다. 월드에 들어오는 연결에는 나와 있는 보스의 자리를 `EnterWorldResult` 뒤에 같은 패킷으로 보내되 종류를 "보스가 나와 있음"으로 달리합니다(등장과 가르려는 것입니다. 클라이언트는 이것으로 시스템 줄과 화면 위의 글을 띄우지 않고 자리만 표시합니다). 클라이언트는 등장을 알림으로 띄우고(채팅의 시스템 줄과 화면 위의 글), 죽음은 채팅의 시스템 줄로 알리고, 지도와 미니맵에 보스의 자리를 표시합니다.
- **소환수**: 마법사의 소환 스킬([전투](#전투))이 부르는, 주인이 있는 개체입니다. 수치는 `Monsters`의 줄(종류가 소환수)에 있고, 어느 줄을 얼마 동안 부르는지는 `Skills`의 줄에 있습니다(처음 값 3분). 한 사람에 하나이고, 다시 부르면 앞의 것이 사라집니다. 스킬이 발동하는 틱에 주인의 자리에 가득 찬 체력으로 나옵니다.
  - **따라가기**: 대상이 없으면 주인의 2 m 안까지 걷습니다. 곧게 걸어갈 수 있으면(`CanWalkLine`) 곧게, 아니면 A*로 가고, 주인이 3 m 넘게 옮기면 길을 다시 찾습니다. 걷는 쪽은 플레이어와 같아 안전 지대를 걷습니다([공간](#공간)). 주인에게서 20 m 넘게 떨어졌거나 길이 없으면 주인의 자리로 순간 이동합니다.
  - **대상**: 주인이 공격을 시작한 대상입니다. 주인이 공격자인 `AttackSwing`의 대상과, 주인이 쓴 피해나 상태 이상을 주는 단일 대상 스킬의 대상입니다(시전 시간이 있는 스킬은 발동한 때부터입니다. 범위 스킬과 직선으로 나는 스킬의 대상은 아닙니다). 스스로 인식하지 않고, 맞아도 때린 쪽으로 대상을 바꾸지 않습니다. 대상이 죽었거나 월드에서 빠졌거나 복귀 중인 몬스터이거나, `CanAttack`(주인과 대상)이 거짓이 됐거나, 대상이 주인에게서 20 m 넘게 떨어졌거나, 주인 둘레 20 m 안에 대상까지의 길이 없거나, 주인이 공격 멈춤을 보냈으면 대상을 버리고 따라가기로 돌아갑니다(주인이 그 대상을 다시 치면 다시 넣습니다).
  - **공격**: 대상을 몬스터의 추적처럼 쫓아가(길은 주인 둘레 20 m 안의 칸에서 찾고, 없으면 몬스터처럼 건너뛰지 않고 대상을 버립니다. 위의 대상) `Monsters`의 사거리, 간격, 타격까지의 시간, 공격력으로 기본 공격을 합니다. 사거리와 선은 소환수의 자리에서 보고, 사건(`AttackSwing`, `Damaged`)의 공격자는 소환수입니다. 피해의 식은 같습니다([전투](#전투)의 피해).
  - **주인이 한 것으로 치는 것**: 소환수의 공격은 주인의 공격입니다. `CanAttack`은 주인과 대상으로 봅니다(주인이 안전 지대 안에 있으면 주인처럼 소환수도 치지 못하고, 대상이 선공 표시가 있거나 무법자인 플레이어일 때만 칩니다. [월드](#월드)의 안전 지대). 소환수가 `AttackSwing`을 낸 틱에 주인의 전투 상태가 새로 시작하고, 대상이 일반 플레이어나 그 소환수면 주인에게 선공 표시가 붙고, 소환수의 타격으로 일반 플레이어가 죽으면 주인의 성향이 내려갑니다([PK](#pk)).
  - **피해 표**: 소환수가 몬스터에게 준 피해는 그 몬스터의 피해 표에 소환수의 줄로 쌓입니다. 편을 가를 때 소환수는 주인의 편(주인의 파티, 없으면 주인)입니다. 경험치, 드롭의 주인, 퀘스트의 횟수는 그 편이 받고(편에서 누가 받는지는 [파티](#파티)와 [퀘스트](#퀘스트)) 소환수는 경험치를 받지 않습니다. 몬스터는 고른 편에서 피해가 가장 큰 플레이어나 소환수를 치므로, 소환수가 주인보다 많이 때렸으면 소환수를 칩니다. 몬스터가 대상을 고를 때 "닿을 수 없음"과 안전 지대에서 건너뛰는 규칙은 대상인 소환수에게도 같습니다. 선공 몬스터는 소환수를 인식하지 않습니다(자기를 때린 소환수만 쫓습니다). 소환수가 죽거나 사라지면 그 줄의 피해를 주인의 줄로 옮깁니다(주인이 표에 없으면 넣습니다). 옮긴 줄이 표에 든 때(틱과 같은 틱 안의 차례)는 주인의 줄과 소환수의 줄 가운데 먼저 든 쪽의 것으로 해, 편이 먼저 든 차례가 바뀌지 않게 합니다. 주인이 죽었거나 주인의 연결이 캐릭터에서 떨어져서 사라진 것이면 옮기지 않고 버립니다.
  - **맞는 것**: 체력과 방어력이 있습니다(`Monsters`의 줄). 몬스터의 공격, 보스의 범위 공격, 다른 플레이어의 공격과 스킬에 맞고 기절과 감속에 걸립니다. 자연 회복이 없고, 회복과 강화 스킬의 대상이 되지 않습니다([범위 밖](#범위-밖)). 경비병은 소환수를 치지 않습니다.
  - **플레이어가 칠 때**: 남의 소환수는 플레이어처럼 강제 공격을 켜야 칩니다. `CanAttack`에서 대상이 누구인지(레벨, 파티원인지, 일반·선공·무법자)는 주인으로 보고, 안전 지대의 규칙에서 대상의 자리는 소환수의 자리로 봅니다. 자기 소환수는 치지 못합니다. 일반 플레이어의 소환수를 공격하기 시작하면 선공 표시가 붙습니다([PK](#pk)). 소환수를 죽여도 성향은 내려가지 않고 주인이 잃는 것도 없습니다. 소환수가 맞아도 주인의 전투 상태는 시작하지 않습니다.
  - **죽음과 사라지는 때**: 체력이 0이 되면 죽고, 몬스터처럼 3초 동안 쓰러진 채 남았다가 사라집니다. 드롭과 경험치는 없습니다. 그 밖에 사라지는 때는 남는 시간이 끝났을 때([예약한 일](#예약한-일)), 주인이 죽었을 때, 주인의 연결이 캐릭터에서 떨어졌을 때(끊김, 로그아웃, 캐릭터 선택으로 나가기. 캐릭터가 월드에 남아도 소환수는 사라집니다), 다시 불렀을 때입니다. 사라진 소환수가 이미 시작한 타격은 적용하지 않습니다(공격자가 월드에서 빠진 경우. [전투](#전투)의 시작과 타격). 저장하지 않습니다.
  - **알리는 것**: 개체로 알립니다. `EntityEnter`가 싣는 것과 시야의 규칙은 [개체](#개체)에 있고, 이동은 몬스터처럼 다음 꺾이는 점과 속도로, 피해·효과·죽음은 전투의 사건으로 알립니다.
  - **고른 이유**: 맞지 않는 소환수는 피해 표와 `CanAttack`을 고치지 않아도 되지만, 몬스터의 공격을 대신 받지 못하고 PK에서 없앨 방법이 주인을 쓰러뜨리는 것뿐입니다. 맞는 소환수는 피해 표의 줄과 `CanAttack`의 대상이 플레이어와 소환수 둘이 됩니다.
  - **드는 것**: 소환한 사람마다 잠들지 않는 AI 개체 하나입니다. 동접 200명 가운데 절반이 소환하면 AI 개체가 몬스터 201마리에 100이 더해집니다. 길찾기 한 번이 보는 칸은 최대 약 1,260칸이고 몬스터의 추적(약 2,800칸)보다 적습니다(계산한 값). 틱 시간은 재지 않았습니다([서버에서 할 것](#서버에서-할-것)).

## 성장

- **경험치와 레벨**: 몬스터를 잡으면 `Monsters`의 경험치를 얻고, `Levels`의 필요 경험치에 따라 레벨이 오릅니다. 경험치는 지금 레벨에서 쌓은 양으로 가지고, 최대 레벨에서는 쌓지 않습니다. 레벨이 오르면 체력과 마나를 채웁니다. 레벨이 오른 것은 `EntityState`(레벨)로 알리고([개체](#개체)의 표시 상태) 본인에게는 경험치 패킷이 갑니다. 죽어서 경험치를 잃어도 레벨은 내려가지 않습니다.
- **스킬 배우기**: 스킬북 아이템을 쓰면 그 스킬을 배웁니다. 스킬마다 직업과 필요 레벨이 있고, 맞지 않으면 실패합니다. 스킬북의 직업과 필요 레벨은 가르치는 `Skills`의 줄에서 읽습니다. 배운 스킬은 퀵슬롯에 올려 씁니다(퀵슬롯 배치는 서버에 저장). 퀵슬롯에 올릴 수 있는 것은 스킬과 물약입니다(8칸이라 스킬 여섯과 물약 둘이 함께 올라갑니다). 물약을 얻었을 때 그 물약이 퀵슬롯에 없고 빈 퀵슬롯이 있으면 서버가 가장 앞의 빈 자리에 올립니다. 스킬을 배웠을 때도 같습니다. 스킬북을 얻는 곳은 [경제](#경제)에 있습니다.
- **처음 상태**: 새 캐릭터는 레벨 1이고, 직업마다 `Classes`에 적힌 기본 무기, 물약, 첫 스킬로 시작합니다. 기본 무기는 입힌 채로 줍니다. 캐릭터를 만드는 트랜잭션에서 처음 상태의 아이템과 스킬을 함께 넣습니다.
- **체험 캐릭터**: 서버를 시연 옵션(`--demo`)으로 띄우면 캐릭터를 만들 때 체험 캐릭터를 고를 수 있습니다. 레벨 20이고 2단계 장비(+3), 직업의 스킬 모두, 물약, 골드, 강화 주문서, 첫째 펫(나와 있음)으로 시작합니다(`Classes`의 "체험용 처음 상태" 열). 혼자 받은 사람이 10분 안에 사냥, 파티, 보스, 강화, PK를 해 볼 수 있게 하려는 것입니다. 체험 캐릭터를 만들 수 있는 서버인지는 `LoginResult`가 알리고, 옵션이 꺼진 서버는 그 요청을 거절합니다. Live 서버는 시연 서버이므로 켭니다.
- **사망**: 죽으면 그 자리에 쓰러지고, 선공 표시와 걸린 효과를 모두 뗍니다(보라색으로 죽은 플레이어가 마을에서 부활하자마자 경비병에게 맞지 않게). 소환수도 사라집니다([몬스터](#몬스터)의 소환수). 쿨다운과 성향은 남습니다. 부활을 누르면 마을의 부활 지점에서(무법자는 [PK](#pk)) 체력의 30%로 다시 시작합니다. 마나는 그대로입니다. 죽은 동안 받는 요청은 [요청 검증](#요청-검증)에, 페널티는 [PK](#pk)에, 죽은 채 접속을 끊은 경우는 [세션](#세션)에, 죽었을 때 클라이언트가 하는 일은 [화면](#화면)의 사망 줄에 있습니다.

- **골드**: 아이템이 아니라 캐릭터의 수입니다. 바닥에 떨어질 때만 `Items`의 골드 줄을 가리키는 바닥 아이템이 되고, 주우면 수로 더해집니다.
- **등급**: 일반, 고급, 희귀, 영웅 네 단계이고 이름의 색을 정합니다. 등급마다 `Items`의 줄이 다르고(능력치가 다릅니다), 어떤 등급이 나오는지는 `DropGroups`의 확률과 `Recipes`의 확률이 정합니다.
- **인벤토리**: 인벤토리 칸 수가 정해져 있고(60칸), 가득 차면 아이템을 줍거나 사지 못합니다(골드는 줍습니다). 가득 찼다는 것은 그 아이템이 들어갈 자리가 없다는 뜻입니다. 빈 칸이 없어도 이미 가진 겹치는 아이템은 그 칸에 더해지므로 들어옵니다.
- **새로 얻은 것**: 인벤토리의 변화를 알리는 패킷은 바뀐 칸과 골드와 함께 "새로 얻은 것"의 목록을 따로 싣습니다. 줄 하나는 아이템과 수, 또는 골드의 금액이고 얻은 까닭이 붙습니다. 얻은 까닭은 줍기(펫의 줍기 포함), 구매, 채집, 제작, 퀘스트 보상, 개발 명령입니다. 벗기, 창고에서 찾기, 상점에 판 값처럼 옮기거나 바꾼 것은 싣지 않습니다. 클라이언트는 이것으로 얻은 것의 알림을 띄우고, 까닭이 줍기면 줍는 소리를 냅니다([화면](#화면)). 한 틱에 여러 변화가 한 패킷에 모여도 줄마다 까닭이 있어 갈립니다.
- **창고**: 마을의 창고 NPC에게 아이템을 맡기고 찾습니다(120칸. 캐릭터마다 하나). NPC 곁(3 m 안, 선이 트임)에서만 됩니다. 창고의 아이템은 죽어도 떨어뜨리지 않습니다(무법자가 장비를 지키는 수단입니다). 창고의 내용은 창고를 열 때 받습니다. 골드는 맡기지 않습니다.
- **펫**: 펫 아이템을 쓰면 그 펫을 가지게 되고 그 펫이 나와 있습니다(아이템은 없어집니다). 캐릭터마다 하나만 가지고, 다른 펫의 아이템을 쓰면 가진 펫이 바뀝니다(같은 펫이면 실패합니다). 가진 펫은 부르고 넣을 수 있습니다. 가진 펫과 나와 있는지는 저장하고, 본인에게는 월드에 들어올 때와 바뀔 때 알립니다.
  - **하는 일**: 줍기뿐입니다. 싸우지 않고 맞지 않으며 성장과 먹이는 없습니다([범위 밖](#범위-밖)). 펫이 나와 있는 동안 서버가 1초마다 그 플레이어의 자리에서 펫의 줍는 거리(`Pets`) 안이고 선이 트인 바닥 아이템 하나를 가까운 것부터 그 플레이어의 인벤토리에 넣습니다. 고르는 것은 자동 사냥이 줍는 것과 같습니다(드롭의 주인이 그 플레이어나 그 파티이거나 주인만 줍는 시간이 지난 것. 플레이어가 떨어뜨린 것은 줍지 않습니다. [자동 사냥](#자동-사냥)). 들어갈 자리가 없는 아이템은 두고(가득의 뜻은 위의 인벤토리), 골드는 늘 줍습니다. 플레이어가 죽었거나 연결이 떨어져 있는 동안에는 줍지 않습니다. 알리는 패킷은 손으로 주울 때와 같습니다. 줍는 틱은 플레이어마다 흩어 둡니다(한 틱에 몰리지 않게).
  - **개체가 아님**: 펫은 서버의 개체가 아닙니다. 서버는 플레이어마다 "나와 있는 펫" 값 하나만 가지고, 그 값은 플레이어의 `EntityEnter`와 `EntityState`가 싣습니다([개체](#개체)). 펫의 자리는 클라이언트가 만듭니다. 주인의 뒤 1.5 m를 따라 걷고, 주인에게서 6 m 넘게 떨어지거나 주인까지 곧게 걸어갈 수 없으면 주인 곁에 다시 놓습니다. 내 펫은 주울 수 있는 바닥 아이템이 줍는 거리 안에 있으면 그쪽으로 달려갑니다(그리기만 하고, 줍는 것은 서버입니다). 대상으로 고를 수 없고 이름표가 없습니다.
  - **고른 이유**: 펫을 서버의 개체로 두면 플레이어마다 움직이는 개체가 하나씩 늘어납니다. 모두가 펫을 부르면 받는 움직임이 두 배가 되어, 시야 55명에서 클라이언트당 15,354 B/s인 이동의 송신량이 최대 그만큼 더 듭니다(계산한 값). 펫은 싸우지 않아 서버가 자리를 알 까닭이 없으므로 값 하나(1바이트)만 싣습니다. 소환수는 사거리와 선을 서버가 봐야 해서 개체입니다([몬스터](#몬스터)의 소환수).
- **장비**: 장비 칸은 여섯(무기, 투구, 갑옷, 장갑, 신발, 장신구)이고 필요 레벨이 있습니다. 무기는 직업마다 다르고(기사는 검, 마법사는 지팡이) 방어구의 장비 칸 다섯은 두 직업이 함께 씁니다. `Items`의 직업 열이 비어 있으면 공용입니다. 직업이나 필요 레벨이 맞지 않는 장비는 입지 못합니다. 입고 벗으면 능력치를 다시 더합니다.
- **강화**: 강화 주문서를 장비에 씁니다. 안전 수치(+3)까지는 늘 성공하고, 그 위로는 `Enchants`의 확률로 성공합니다. 안전 수치는 따로 상수를 두지 않고 `Enchants`의 +1에서 +3 줄의 확률을 100%로 두어 나타냅니다. 실패하면 장비가 사라집니다. 입은 장비도 강화할 수 있고, 가장 높은 수치(+9)에서의 요청은 실패합니다. 주문서 소모, 난수, 결과는 한 틱에서 정해지고, 저장은 5초 바뀜 표시를 따릅니다([저장의 흐름](#저장의-흐름)).
- **귀환 주문서**: 쓰면 `Items`의 쓰는 시간(3초) 동안의 진행 중인 일(귀환)이 시작합니다([전투](#전투)). 끝나는 틱에 주문서가 없어지고 마을의 부활 지점으로, 무법자는 무법자의 부활 지점으로 옮깁니다. 전투 상태에서는 쓸 수 없습니다(싸우다 빠져나가지 못하게).
- **드롭**: 몬스터가 죽으면 `DropGroups`와 서버의 난수로 골드와 아이템을 정해 죽은 자리에서 1.5 m 안에(처음 값) **바닥 아이템** 개체로 둡니다. 놓을 점이 막힌 칸이거나 죽은 자리에서 그 점까지 선이 막혔으면 죽은 자리에 놓습니다(벽 안이나 벽 너머에 떨어져 줍지 못하는 일이 없게).
- **드롭의 주인**: 몬스터가 죽는 순간에 정합니다. 피해 표([몬스터](#몬스터))에서 피해의 합이 가장 큰 쪽이 파티면 파티 번호, 아니면 플레이어 번호입니다. 주인만 줍는 시간(10초) 동안은 주인만 줍고(주인이 파티면 주울 때 그 파티에 있는 사람이 줍습니다), 그 뒤에는 누구나 줍습니다. 떨어진 지 60초가 지나면 사라집니다.
- **떨어뜨리기**: 인벤토리의 아이템을 바닥에 내려놓습니다. 떨어뜨린 플레이어의 자리에 놓입니다. 떨어뜨린 사람이 파티에 있으면 본인과 파티원만 10초 동안 줍고 그 뒤에는 누구나 줍습니다. 파티가 없으면 주인만 줍는 시간 없이 바로 누구나 줍습니다. 남는 시간은 드롭과 같습니다(60초). 골드는 떨어뜨릴 수 없고, 안전 지대에서도 됩니다. 플레이어끼리 아이템을 건네는 방법입니다. 처리하는 순서와 저장은 [저장의 흐름](#저장의-흐름)에 있습니다.
- **줍기**: 가까이에서 줍기를 보내면 서버가 그 틱에 먼저 온 요청 하나만 받아 줍니다. 바닥 아이템이 알리는 것(주인, 주인만 줍는 시간이 끝나는 틱, 플레이어가 떨어뜨렸는지 등)은 [개체](#개체)의 `EntityEnter`에 있고, 자동 사냥이 무엇을 주울지를 이것으로 정합니다([자동 사냥](#자동-사냥)). 강화한 장비를 떨어뜨려도 수치가 남습니다.
- **요청 번호**: 인벤토리를 바꾸는 요청(아이템 사용(귀환 주문서 포함), 입기와 벗기, 강화, 떨어뜨리기와 줍기, 구매와 판매, 창고에 맡기기와 찾기, 제작의 시작, 퀘스트 받기와 완료)은 요청 번호를 싣습니다. 시작에 성공한 귀환과 제작은 `RequestResult`(성공) 뒤에 `Progress`로 진행을 알립니다. 채집의 시작, 창고 열기, 펫 부르기·넣기는 요청 번호가 없습니다(실패는 `ActionFailed`). 번호는 답(`RequestResult`)을 짝짓는 데만 씁니다(답이 가는 길은 [요청 검증](#요청-검증)). 번호를 저장하지는 않습니다. TCP는 한 연결 안에서 같은 요청을 두 번 전하지 않고, 다시 연결하면 클라이언트가 인벤토리를 처음부터 다시 받아 기다리던 요청을 다시 보내지 않기 때문입니다.

## 파티

- 초대 → 수락으로 만들고, 떠나기와 내보내기가 있습니다. 초대와 내보내기는 파티장만 합니다. 초대는 시야 안의 대상에게만 하고, 30초 안에 답하지 않으면 사라집니다. 답을 기다리는 초대가 있는 대상에게 또 초대하면 실패합니다. 초대받은 쪽이 거절하면 초대를 바로 지우고 초대한 쪽에 실패 알림("초대를 거절함")으로 알립니다. 최대 5명입니다(`Constant`).
- 파티장이 떠나면 가장 먼저 들어온 파티원이 파티장이 됩니다. 한 명만 남으면 파티가 없어집니다.
- 연결이 캐릭터에서 떨어지면(끊김, 로그아웃, 캐릭터 선택으로 나가기) 그 캐릭터는 파티에서 빠집니다.
- 파티원의 체력과 위치는 시야 밖이어도 보입니다(파티 전용 패킷, 1초마다). HUD의 파티원 칸을 눌러 그 파티원을 대상으로 삼습니다(회복과 강화를 쓰기 쉽게. 되는 조건은 [화면](#화면)의 조작 표).
- 경험치는 잡은 자리의 둘레 9개의 시야 칸에 있는 파티원이 받습니다. 죽어 있는 파티원은 받지 않습니다. 그 몬스터의 경험치를 받는 파티원이 한 명 늘 때마다 합이 10%씩 늘고(2명이면 +10%, 5명이면 +40%), 는 합을 받는 인원으로 나눕니다. 나눈 경험치의 끝수는 버립니다.
- 드롭의 주인이 파티일 때 누가 줍는지는 [아이템](#아이템)의 드롭의 주인에 있습니다.
- 파티원끼리는 피해를 주지 못하고, 회복과 강화 스킬을 파티원에게 쓸 수 있습니다([전투](#전투)). 파티 채팅이 있습니다.

## PK

- **어디서**: 안전 지대 밖이면 어디서나 다른 플레이어를 공격할 수 있습니다. 레벨 10 미만은 공격하지도 받지도 않습니다. 안전 지대가 누구를 지키는지는 [월드](#월드)의 안전 지대에 있습니다.
- **강제 공격**: 다른 플레이어는 강제 공격을 켜야 공격합니다(실수로 치지 않게). PC는 `Ctrl`을 누르고 있는 동안이고, 모바일은 켜고 끄는 버튼입니다.
  - `UseSkill`의 강제 공격 표시는 필드 하나입니다. 서버는 범위 스킬과 직선으로 나는 스킬에서만 그 값을 보고, 단일 대상 스킬에서는 보지 않습니다.
  - 대상을 실은 요청(공격 시작, 단일 대상 스킬)에서 서버는 `CanAttack`만 봅니다. 플레이어를 공격 대상으로 삼으려면 클라이언트에서 강제 공격을 켜야 하기 때문입니다.
  - 범위 스킬과 직선으로 나는 스킬은 표시가 없으면 플레이어와 남의 소환수는 맞지 않습니다(지나갑니다). 표시가 있으면 `CanAttack`을 통과한 플레이어와 소환수가 맞고, 선공 표시의 규칙이 적용됩니다.
- **`CanAttack`**: 공격할 수 있는 사이인지를 서버가 보는 확인입니다. 안전 지대의 규칙([월드](#월드))에 걸리지 않아야 하고, 플레이어끼리는 둘 다 레벨 10 이상이고 파티원이 아니어야 합니다. 대상이 소환수일 때의 규칙은 [몬스터](#몬스터)의 소환수에 있습니다. 요청을 받을 때, 기본 공격의 다음 공격 틱마다, 타격할 틱, 시전이 끝나는 틱에 보고, 범위 스킬·직선으로 나는 발사체·보스의 범위 공격이 맞힐 개체를 고를 때와 소환수가 대상을 칠 때도 봅니다([전투](#전투), [몬스터](#몬스터)).
- **일반 플레이어**: 아래 표의 일반(흰색)만을 뜻합니다. 선공 표시가 있거나 무법자인 플레이어는 일반 플레이어가 아닙니다.
- **선공 표시**: 일반 플레이어나 그 소환수를 대상으로 공격을 시작한 틱에 붙습니다. 내 소환수가 그런 대상에게 `AttackSwing`을 낸 틱에도 주인인 내게 붙습니다([몬스터](#몬스터)의 소환수). 공격을 시작한 틱은 [전투](#전투)의 전투 상태와 같아, 기본 공격은 `AttackSwing`을 낸 틱이고 단일 대상 스킬은 `SkillUsed`를 낸 틱이며, 시전 시간이 있는 단일 대상 스킬은 시전을 시작한 틱에도 붙습니다. 범위 스킬과 직선으로 나는 스킬은 일반 플레이어나 그 소환수가 맞은 틱에 붙습니다. 30초 동안 이름이 보라색이 되고, 다시 그러면 30초가 새로 시작합니다. 보라색인 플레이어는 누가 죽여도 죽인 쪽에 대가가 없습니다(정당방위).
- **성향**: 일반 플레이어를 죽이면 성향이 100 내려가고, 0보다 낮으면 이름이 빨간색(무법자)이 됩니다. 내려가는 것은 죽인 타격을 준 한 명입니다(소환수의 타격이면 그 주인입니다. [몬스터](#몬스터)의 소환수). 죽은 쪽의 상태(일반, 선공, 무법자)는 죽어서 선공 표시를 떼기([성장](#성장)의 사망) 전의 것으로 봅니다. 몬스터를 잡으면 그 몬스터의 경험치를 받은 모두가 5씩 오르고, 0보다 올라가지 않습니다. 무법자가 선공 표시도 가지면 이름은 빨간색입니다. 성향은 저장합니다.

| 상태 | 이름 색 | 죽었을 때 | 그 밖 |
| --- | --- | --- | --- |
| 일반 | 흰색 | 지금 레벨에서 쌓은 경험치의 5%를 잃음. 아이템은 떨어뜨리지 않음 | |
| 선공 | 보라색 | 일반과 같음 | 경비병이 공격함. 죽여도 대가 없음 |
| 무법자 | 빨간색 | 지금 레벨에서 쌓은 경험치의 10%를 잃고, 인벤토리의 무작위 한 칸을 50% 확률로, 입은 장비 가운데 무작위 하나를 10% 확률로 떨어뜨림 | 경비병이 공격함. 죽여도 대가 없음 |

- **사망 페널티의 값**: 위 표의 값은 처음 값입니다. 레벨은 내려가지 않습니다([성장](#성장)).
- **떨어뜨린 아이템**: 인벤토리에서는 차 있는 인벤토리 칸 가운데 하나를 뽑고, 겹친 칸은 통째로 떨어뜨립니다. 인벤토리(50%)와 입은 장비(10%)는 따로 굴립니다. 놓는 자리는 몬스터의 드롭과 같습니다([아이템](#아이템)의 드롭). 무법자가 죽어서 떨어뜨린 것은 바닥 아이템이 되어 누구나 주울 수 있습니다. 몬스터의 드롭과 같은 전리품이라 자동 사냥도 줍습니다("플레이어가 떨어뜨림" 표시를 붙이지 않습니다). 아이템을 내놓는 일이라 [저장의 흐름](#저장의-흐름)의 내놓는 순서를 따릅니다.
- **경비병**: 마을의 가장자리의 놓인 점에 서 있는 NPC이고 여럿입니다(수는 [콘텐츠의 양](#콘텐츠의-양)). 공격 대상이 아닙니다(체력이 없습니다). 인식 범위에 선공 표시가 있거나 무법자인 플레이어가 들어오면 쫓아가 치고(여럿이면 가장 가까운 쪽, 거리가 같으면 개체 번호가 작은 쪽을 고르고, 쫓는 동안에는 바꾸지 않습니다), 추적 한계를 넘거나, 대상이 죽었거나 월드에서 빠졌거나, 대상이 일반 플레이어로 돌아왔거나(선공 표시가 끝났고 무법자도 아님), 추적 한계 안에 대상까지의 길이 없으면 놓인 점으로 돌아갑니다. 플레이어와 같은 걷는 쪽이라 안전 지대를 걷습니다([공간](#공간)). 수치는 `Npcs`의 줄이 가리키는 `Monsters`의 줄에 있습니다(쓰는 열은 [데이터 테이블](#데이터-테이블)).
- **무법자의 부활**: 마을이 아니라 마을 밖에 따로 둔 지점에서 부활합니다. 부활하자마자 경비병에게 다시 죽지 않게, 그 지점은 경비병의 인식 범위 밖이어야 합니다([월드](#월드)의 맵 원본 검증).
- **끊어서 피하기**: 할 수 없습니다([세션](#세션)의 월드에 남는 캐릭터).

## 생활

- **채집**: `GatherNodes`의 채집물이 `Spawns`대로 필드에 있습니다([몬스터](#몬스터)). 채집물마다 필요 레벨이 있습니다. 채집은 가까이에서 시작하는 진행 중인 일이고(공통 규칙은 [전투](#전투)), 채집 시간(3초)이 지난 틱에 재료를 얻습니다. 끝나는 틱에 인벤토리가 가득이면 실패하고 채집물의 횟수는 줄지 않습니다. 채집물은 횟수를 다 쓰면 사라졌다가 다시 나오고, 그때 같은 채집물을 채집하던 다른 플레이어의 채집은 취소됩니다.
- **제작**: 마을의 제작 NPC 곁에서 `Recipes`의 제작법을 골라 시작하는 진행 중인 일입니다. 시작할 때 재료, 골드, 결과가 들어갈 자리를 확인하고, 하나라도 모자라면 시작할 수 없습니다. 끝나는 틱에 같은 확인을 다시 하고, 통과하면 재료와 골드를 빼고 결과를 넣습니다. 통과하지 못하면 실패합니다. 제작법마다 필요 레벨이 있고, 장비 제작법은 결과의 등급을 `Recipes`의 확률로 정합니다.
- 물약과 장비를 얻는 곳은 [경제](#경제)에 있습니다.

## 경제

- **골드가 생기는 곳**: 몬스터 드롭, NPC 상점에 팔기, 퀘스트 보상.
- **골드가 사라지는 곳**: NPC 상점 구매, 제작비.
- **NPC 상점**: `Shops`의 물건을 사고, 가진 것을 정해진 값에 팝니다.
- **얻는 곳**: 상점에서 사는 것은 1단계 물약, 귀환 주문서, 강화 주문서, 직업마다 둘째와 셋째 스킬의 책, 첫째 펫의 아이템입니다. 넷째와 다섯째 스킬의 책은 사냥터 2와 3의 몬스터와 보스가, 여섯째 스킬의 책은 사냥터 3의 몬스터와 보스가 떨어뜨립니다(스킬의 차례는 [전투](#전투)의 직업의 스킬). 둘째 펫의 아이템은 보스가 떨어뜨립니다. 2단계 물약은 제작으로만 얻습니다. 1단계 장비는 사냥터 1의 드롭으로, 2단계 장비는 사냥터 2와 3의 드롭과 제작 둘 다로, 3단계 장비는 제작으로만 얻습니다.
- **플레이어 사이**: 거래소와 개인 거래는 없습니다([범위 밖](#범위-밖)). 아이템은 바닥에 [떨어뜨려](#아이템) 건넵니다.

## 사회

- **채팅**: 채널은 주변(둘레 9개의 시야 칸), 파티, 전체, 귓속말입니다. 채팅창의 시스템 줄(보스 등장 등)은 채널이 아닙니다. 서버가 글을 보내는 것이 아니라 클라이언트가 알림 패킷을 받아 `Strings`로 만드는 줄입니다. 주변 채팅은 보낸 사람의 둘레 9개의 시야 칸에 있는 플레이어에게 가고, 받는 쪽이 보낸 사람의 개체를 받았는지와 상관없습니다. 그래서 보낸 사람의 이름을 함께 싣고, 말풍선은 그 캐릭터가 화면에 있을 때만 띄웁니다. 시야 밖의 플레이어에게는 채팅창에서 이름으로 귓속말을 보냅니다. 귓속말은 보낸 쪽에도 돌려 보냅니다(받는 사람의 이름과 함께). 길이와 보내는 빈도는 서버가 제한하고, 넘은 글은 실패 알림으로 답합니다. 한 줄은 UTF-8로 180바이트(한글 60자)까지이고 초당 2번까지입니다. 길이는 클라이언트 패킷의 상한(256바이트)을 넘지 않게 하려는 것입니다.

## 퀘스트

- `Quests`의 퀘스트를 마을 NPC에게서 받아 차례로 합니다. 한 번에 하나만 진행합니다. 조건은 몬스터 잡기, 재료 모으기, 제작하기, 레벨 달성, 장비 입기입니다. 장비 입기 조건은 장비 칸으로 나타내고, 그 칸에 무엇이든 입으면 채워집니다.
- 진행은 서버가 세고 저장합니다. 상태를 보는 조건(레벨, 장비, 모으기)은 지금 상태로 보고, 횟수를 세는 조건(잡기, 만들기)은 받은 뒤부터 셉니다. 파티원이 잡은 몬스터도 내가 경험치를 받았으면 셉니다. 모으기의 재료는 완료할 때 뺍니다. 보상을 받을 때 인벤토리에 자리가 없으면 끝낼 수 없습니다.
- 처음 들어온 플레이어를 사냥 → 장비 → 채집 → 제작 순으로 안내하는 것이 목적입니다.
- 퀘스트 NPC의 머리 위에 받을 수 있는지와 끝낼 수 있는지를 표시하고, 미니맵과 전체 지도에 목표의 자리를 보입니다. 목표의 자리는 테이블에 두지 않고, 클라이언트가 `Spawns`(몬스터, 채집물)와 `Npcs`에서 내 자리에 가장 가까운 자리를 구합니다. 모으기의 재료가 몬스터 부산물이면 그 몬스터의 무리의 자리가 목표입니다. 레벨과 장비 조건은 목표의 자리가 없습니다.
- **목표까지 걷기**: 퀘스트 창이나 지도에서 목표를 누르면 길찾기로 그곳까지 걷습니다. PC와 모바일 모두 되고, 이동 입력(WASD, 조이스틱)을 넣으면 멈춥니다. 눌러서 이동과 같은 길찾기를 씁니다([공간](#공간)).

## 자동 사냥

- 클라이언트가 합니다. 서버에는 손으로 한 것과 같은 패킷이 갑니다. 스킬도 손으로 쓸 때와 같은 길로 보내, 시전 시간이 있는 스킬은 캐릭터를 세우고 위치를 보낸 뒤에 보냅니다([전투](#전투)의 진행 중인 일).
- 차례: 가까운 몬스터를 대상으로 → 사거리 안이고 선이 트인 곳(안전 지대 밖. [전투](#전투)의 기본 공격)까지 이동 → 기본 공격과 쿨다운이 돈 스킬 → 죽으면 바닥 아이템 줍기 → 다음 대상. 지금 대상이 자동 사냥이 고를 수 있는 것(아래)이 아니면 치러 가지 않고, 대상이 죽었을 때처럼 바닥 아이템을 주운 뒤 다음 대상을 고릅니다(손으로 고른 플레이어, 파티원, 소환수, 보스를 치지 않게). 강화와 소환은 대상까지의 거리와 상관없이 다가가기 전에 그 자리에서 씁니다. 이 차례의 어디에서든 판단할 때마다 먼저 체력과 마나를 보고, 기준 아래면 회복 스킬이나 물약을 씁니다(기준은 `Constants`의 값이고 처음 값 30%. 어느 쪽을 쓰는지는 아래). 다만 내가 기절해 있거나, 내 진행 중인 일(시전 등)이 있거나, 보낸 스킬이나 물약의 답을 기다리는 동안은 체력과 마나도 보지 않고 기다립니다(움직이면 시전이 취소되고 다른 요청은 실패하므로).
- 시작한 자리에서 30 m 안의 몬스터만 고르고, 보스는 고르지 않습니다. 줍는 범위도 시작한 자리에서 30 m입니다. 죽으면 꺼집니다.
- 스킬과 물약은 퀵슬롯에 올린 것만 앞자리부터 씁니다(앞자리부터는 같은 구실의 것이 여럿일 때의 차례입니다). 피해 스킬과 기절 스킬은 쿨다운이 돌 때마다(중심이 자기인 범위 스킬은 대상이 그 범위 안에 있을 때), 강화는 그 효과가 없을 때, 소환은 내 소환수가 없을 때, 회복 스킬은 체력이 물약 기준 아래일 때 쓰고(퀵슬롯에 쓸 수 있는 회복 스킬이 없거나 쿨다운이거나 마나가 모자라면 체력 물약을 씁니다), 마나가 30% 아래면 마나 물약을 씁니다. 쓸 수 있는 회복 스킬과 물약이 없으면 그 판단을 건너뛰고 사냥을 이어 갑니다. 들어갈 자리가 없는 아이템은 줍지 않고(가득의 뜻은 [아이템](#아이템)의 인벤토리), 골드는 늘 줍습니다.
- 가까운 것은 직선거리로 고릅니다. 걸어갈 길이 없는 몬스터와 바닥 아이템, 공격이나 스킬이 "공격할 수 없는 대상"으로 실패한 몬스터(복귀 중인 몬스터. 시전의 끝에 같은 이유로 취소된 것도)는 10초 동안 후보에서 빼고, 다가가는 동안 3초 동안 대상에 가까워지지 못하면 그 대상도 10초 동안 후보에서 빼고 다음 대상을 고릅니다(기다리는 동안은 세지 않습니다. 빼지 않으면 가장 가까운 그 대상이 다시 뽑힙니다). 벽 너머의 가까운 대상에 매달리지 않게 하려는 것입니다.
- 창을 열어도 자동 사냥은 계속됩니다. 창이 열린 동안 막는 것은 새로 하는 손 조작(새로 누르는 이동, 대상 고르기)뿐이고, 걷던 경로(눌러서 이동, 목표까지 걷기)는 이어 걷습니다. 손으로 조작하면 자동 사냥이 2초 멈춥니다(처음 값). 자동 사냥 중에는 화면이 꺼지지 않게 합니다.
- 줍는 것은 주인이 나나 내 파티이거나 주인만 줍는 시간이 지난 바닥 아이템입니다([아이템](#아이템)의 드롭의 주인). 남의 드롭으로 걸어가지 않습니다. 플레이어가 떨어뜨린 아이템은 줍지 않습니다. 가방을 비우려고 떨어뜨린 것을 다시 줍거나, 남에게 건네려고 떨어뜨린 것을 가로채지 않게 하려는 것입니다. 펫이 나와 있으면 내 자리에서 펫의 줍는 거리 안에 있는 것은 걸어가지 않고 펫에게 맡깁니다([아이템](#아이템)의 펫).
- 무엇을 할지 고르는 판단은 엔진 없는 코드로 만들어 테스트하고, 이동과 입력만 엔진 쪽에서 합니다.

## 콘텐츠의 양

처음 넣을 양입니다. 구조를 보이는 데 필요한 만큼만 두고, 늘리는 것은 데이터의 줄을 더하는 일입니다.

- **수치를 잡는 기준**: 1레벨에서 30레벨까지 자동 사냥으로 2시간쯤 걸리게 합니다. 시연에서 성장이 보여야 하기 때문입니다. 레벨마다 필요한 경험치는 이 시간에서 거꾸로 구하고, 몬스터의 체력은 같은 레벨의 캐릭터가 스킬 몇 번에 잡는지로 정합니다.
- **그림**: 필요한 메시(캐릭터, 몬스터, NPC, 채집물과 환경: 땅, 건물, 나무, 바위, 울타리, 테두리의 산, 막지 않는 장식(풀, 꽃)), 애니메이션, 아이콘, 글꼴, 소리의 목록과 출처는 `docs/art.md`에 둡니다. 직접 만든 것이나 CC0만 넣고, 그림이 없는 것은 자리 표시(색 도형, 글자 아이콘)로 둡니다.

- **모바일**: 이동은 조이스틱만 씁니다(땅을 눌러 이동하지 않습니다). 짧게 누르면(탭) 위 표의 누름이고, 끌면 카메라가 돕니다. 카메라는 화면 끌기와 두 손가락 벌리기로 돌리고 당깁니다. 터치 기기에서만 보이는 것은 조이스틱과 공격·상호작용·대상 고르기·강제 공격 버튼입니다. 퀵슬롯은 PC와 모바일 모두 보입니다(PC는 키 표시가 붙은 칸이고 눌러도 됩니다). 버튼은 손가락으로 누를 최소 크기(약 9 mm)를 지킵니다. PC에서는 버튼에 키 표시를 붙입니다.
- **터치 나눔**: 손가락마다 주인이 하나입니다(조이스틱, 버튼, 카메라). 조이스틱을 쥔 채 스킬 버튼을 누르고 다른 손가락으로 카메라를 돌릴 수 있습니다.
- **화면 크기**: 기준 해상도는 1920×1080이고, UI 배율은 화면의 짧은 변으로 정합니다(UMG의 DPI 배율 곡선). 화면 비율 16:9에서 21:9까지 HUD의 요소는 가까운 모서리에 붙이고(앵커), 창은 가운데에 정한 폭으로 둡니다.
- **안전 영역**: HUD와 창의 뿌리를 안전 영역 위젯으로 감싸 펀치홀과 둥근 모서리를 피합니다.
- **공통 모양**: 색, 글꼴 크기, 버튼·탭·목록·창 틀의 모양을 위젯 생성기의 한 곳(스타일 표)에 두고 모든 화면이 그것을 씁니다. 창마다 따로 모양을 정하지 않습니다. 배치의 원본이 생성기 코드이므로 화면 크기와 안전 영역의 규칙도 생성기에 넣습니다.
- **기기에 남기는 것**: 설정(소리, 품질, 프레임 상한, 언어, 카메라 흔들림), 마지막으로 쓴 ID, 조작 안내를 본 캐릭터입니다. 조작 안내를 봤는지는 서버 주소와 캐릭터 번호로 남깁니다. 서버에는 남기지 않습니다.
- **실패, 확인, 수량**: 실패한 요청은 이유를 알림 층에 짧은 글로 띄웁니다(`FailReason`마다 글 하나. 실패가 오는 길은 [요청 검증](#요청-검증)). 내 진행 중인 일이 끝나는 틱의 확인에서 취소된 것(`ProgressCancelled`)도 그 이유를 같은 곳에 띄우고, 중간에 취소된 것("취소됨")과 남의 것은 띄우지 않습니다([전투](#전투)의 진행 중인 일). 확인 팝업과 수량 입력을 쓰는 곳은 위의 표에 있습니다.
- **글 입력**: 글을 입력하는 동안은 이동과 단축키를 막습니다. 단축키는 글자가 아니라 키 코드로 읽어, 한글 입력기가 켜져 있어도 같은 키로 동작합니다.
- **창과 조작**: 창이 열린 동안 무엇을 막는지는 [자동 사냥](#자동-사냥)에 있습니다. 요청의 답을 기다리는 버튼은 누를 수 없게 합니다.
- **카메라의 충돌**: 카메라가 놓일 자리가 건물이나 테두리의 산 안이면 밖으로 나올 때까지 당깁니다. 나무, 바위, 울타리는 카메라를 막지 않습니다. 캐릭터가 건물 뒤에 가려지는 것은 그대로 둡니다. 그래서 캐릭터에서 카메라까지의 선을 보는 스프링 암의 충돌은 쓰지 않습니다(가리기만 해도 카메라를 당김. 2026-11-13 88에서 봄).
- **게임 종료**: 설정 창의 버튼으로 끝냅니다(Android도 같습니다). 월드 안에서 끝낼 때 거치는 길은 [세션](#세션)의 로그아웃에 있습니다.
- **소리**: 타격과 스킬, UI(버튼, 창, 강화 결과, 레벨 업, 줍기), 발소리, 구역마다의 배경음을 틉니다. 효과와 배경 두 묶음으로 나눠 설정의 크기와 잇고, 같은 소리는 한 번에 8개까지 틉니다(처음 값).
- **시연**: 시연 표시(프레임, 보이는 캐릭터 수, 지연)는 설정 창의 줄로 켜고, Shipping 빌드에서도 켤 수 있습니다. UI 숨기기와 자유 카메라는 개발 빌드의 키로 켭니다.
- **개발용 표시**: 다른 개체의 서버 위치와 그린 위치, 내 길찾기 경로, 막힌 칸, 넣은 지연(지연과 손실을 흉내 내는 옵션)을 보입니다. 개발 빌드에서 `F3`으로 켭니다. 보간과 길찾기를 영상으로 보이는 데 씁니다.
- **연출**: 아래 표의 것을 둡니다. 수치는 데이터 테이블에, 동작·이펙트·소리·아이콘·구역의 색은 클라이언트의 표현 표(템플릿 번호 → 에셋)에만 둡니다. 데이터 테이블에 표현의 키를 두지 않습니다. 예외는 `MapObjectKinds`의 "메시의 키"입니다(두 엔진이 같은 맵을 만들어야 하므로 맵의 종류 표만 메시의 키를 가집니다).

| 때 | 연출 |
| --- | --- |
| 기본 공격 | 동작, 타격 이펙트와 소리 |

| 피격 | 번쩍임, 피격 동작, 체력 바. 피해 숫자는 나와 내 소환수가 주거나 받은 피해만 띄움(한 화면 200명에서 숫자가 화면을 덮지 않게) |

## 데이터 테이블

`data/`의 xlsx가 원본이고 data-tool이 테이블마다 `.proto`와 Protobuf 바이너리를 냅니다. 서버(C#), Unity(C#), Unreal(C++)은 protoc가 만든 코드로 읽습니다. 이름이 있는 테이블(`Zones`, `Monsters`, `Items`, `Skills`, `Npcs`, `GatherNodes`, `Quests`, `Pets`)은 모두 이름 열(`Strings`의 키)을 가지고, 그 밖의 문장도 `Strings`의 키로 가리킵니다. 맵은 테이블이 아니라 격자와 놓인 것의 목록으로 냅니다([월드](#월드)). 테이블의 열은 이 표가 원본입니다.

| 테이블 | 내용 |
| --- | --- |
| `Constants` | 밸런스의 수입니다(값은 처음 값이고 수치를 맞출 때 바꿉니다). 필드의 크기(한 변 600 m), 인벤토리 칸 수(60), 창고 칸 수(120), 전투 상태 시간(5초), 선공 표시 시간(30초), PK를 할 수 있는 레벨(10), 드롭이 남는 시간(60초. 플레이어가 떨어뜨린 것도 같음), 주인만 줍는 시간(10초), 드롭을 흩는 거리(1.5 m), 플레이어의 반지름. 성향(일반 플레이어를 죽이면 −100, 몬스터를 잡을 때마다 +5이고 0보다 올라가지 않음, 0보다 낮으면 무법자). 사망 페널티(일반과 선공은 지금 레벨에서 쌓은 경험치의 5%, 무법자는 10%와 인벤토리의 무작위 한 칸 50%, 입은 장비 가운데 무작위 하나 10%), 부활할 때의 체력(30%). 회복(전투 상태가 아닐 때는 초당 최대 체력·마나의 5%, 전투 상태에서는 1%). 치명타의 확률과 배수(5%, 1.5배), 파티 경험치 보너스(경험치를 받는 파티원이 한 명 늘 때마다 +10%), 파티 초대의 만료(30초). 몬스터(죽은 몬스터가 남는 시간 3초, "닿을 수 없음"의 시간 5초, 길을 다시 찾는 대상의 이동 거리 3 m, 복귀할 때 범위에 더하는 거리 4 m, 복귀 중의 회복 초당 최대 체력의 20%, 배회에서 서 있는 시간 3–6초). 채팅(한 줄은 UTF-8로 180바이트, 초당 2번까지). 상호작용(3 m 안에서 실행, 상호작용 버튼이 고르는 것은 10 m 안의 가장 가까운 것). 자동 사냥(시작한 자리에서 30 m 안, 체력 물약 기준 30%, 마나 물약 기준 30%, 대상을 후보에서 빼는 시간 10초(길이 없거나, 공격할 수 없거나, 가까워지지 못한 대상), 대상을 바꾸는 시간 3초(이만큼 가까워지지 못하면 뺍니다), 손 조작 뒤 멈추는 시간 2초). 이동 알림(방향이 마지막으로 알린 값에서 `yaw` 8단위 넘게 달라지면 알리고 4틱에 한 번까지, 확인 간격 10틱, `Move`가 없어 멈춤으로 알리기까지 10틱, 몬스터 목적지 알림의 간격 10틱). 시야(경계의 여유 8 m, 시야 인원 상한 200). 소환수(따라가 서는 거리 2 m, 주인에게서 떨어질 수 있는 거리 20 m). 펫의 줍는 간격(1초). 요청의 빈도 제한(버킷의 토큰 40개, 초당 채우는 수 30개, 요청을 버리는 일이 이어져 끊기까지 3초, 버린 것이 없어 다시 세기까지 1초) |
| `Zones` | 구역의 사각형(작은 모서리의 칸부터 큰 모서리 바로 앞의 칸까지 덮음), 종류, 안전 지대, 권장 레벨(아래와 위 두 열), 부활 지점과 무법자의 부활 지점(마을의 줄에 둠) |
| `MapObjectKinds` | 맵에 놓는 것의 종류마다 차지하는 칸의 가로·세로(미터, 정수), 막는지, 카메라를 막는지, 메시의 키. 놓인 자리는 테이블이 아니라 텍스트 파일([월드](#월드)) |
| `Classes` | 직업마다 기본 공격의 사거리와 간격, 타격까지의 시간, 기본 공격 발사체의 속도(기사는 없음), 처음 상태(기본 무기, 물약, 첫 스킬), 체험용 처음 상태(펫 포함) |
| `Levels` | 직업과 레벨마다 한 줄. 필요 경험치, 기본 능력치 |
| `Monsters` | 종류(일반, 보스, 소환수, 경비병), 레벨, 체력, 공격력, 방어력, 이동 속도, 반지름, 인식 범위, 추적 한계, 공격 사거리와 간격, 타격까지의 시간, 발사체의 속도(원거리 몬스터만), 선공 여부, 쓰는 스킬(보스의 범위 공격은 `Skills`의 줄), 경험치, 드롭 묶음. 경비병도 이 표의 줄이고 공격력, 사거리, 공격 간격, 타격까지의 시간, 이동 속도, 인식 범위, 추적 한계를 씀. 소환수의 줄은 체력, 공격력, 방어력, 반지름, 사거리, 공격 간격, 타격까지의 시간, 이동 속도를 씀 |
| `Spawns` | 자리, 몬스터나 채집물, 수, 흩는 반경, 다시 나오는 시간, 배회 반경 |
| `Skills` | 직업, 종류, 계수, 사거리, 범위, 중심(대상, 자기), 쿨다운(보스의 범위 공격에서는 공격의 간격), 시전 시간, 타격까지의 시간, 예고 시간(보스의 범위 공격. 처음 값 1.5초), 마나, 필요 레벨, 발사체의 속도(직선으로 나는 스킬만), 거는 효과(`Effects`의 줄), 부르는 것(`Monsters`의 줄)과 남는 시간(소환 스킬만) |
| `Effects` | 종류(기절, 감속, 공격력·방어력 올림), 값, 지속 시간 |
| `Items` | 종류, 종(같은 장비의 등급 넷을 묶는 번호), 등급, 장비 칸, 능력치, 필요 레벨, 직업(비우면 공용. 스킬북은 필요 레벨과 직업을 비우고 가르치는 `Skills`의 줄을 따름), 겹침(겹치는지 아닌지만 정함. 한 인벤토리 칸의 상한은 없음), 상점에 파는 값, 쓰는 종류(체력 회복, 마나 회복, 귀환, 스킬 배우기, 강화, 펫 얻기)와 값(회복량, 스킬 번호, `Pets`의 줄), 쓰는 시간(귀환 주문서 3초, 나머지 0), 물약의 쿨다운 |
| `Enchants` | 강화 단계별 확률과 능력치(그 장비의 `Items` 능력치에 곱하는 비율). 안전 수치를 나타내는 방법은 [아이템](#아이템)의 강화 |
| `DropGroups` | 묶음마다 아이템, 확률, 수량, 골드 |
| `Npcs` | NPC의 자리와 역할(경비병이면 `Monsters`의 줄). 상점, 창고, 제작, 퀘스트 NPC는 하나씩이라 `Shops`와 `Quests`는 NPC를 가리키지 않고, 요청에도 NPC를 싣지 않음. 경비병은 여럿임([PK](#pk)) |
| `Shops` | 아이템, 사는 값(상점이 하나라 상점을 가리키는 열은 없음) |
| `Pets` | 펫마다 줍는 거리. 얻는 아이템은 `Items`의 줄이 이 표를 가리킴 |
| `GatherNodes` | 채집물의 종류, 주는 재료와 수량, 채집 시간, 횟수, 필요 레벨(다시 나오는 시간은 `Spawns`에 둠) |
| `Recipes` | 제작법의 결과(물약이면 `Items`의 줄, 장비면 종), 재료와 수량, 골드, 제작 시간, 필요 레벨, 장비면 등급의 확률 |
| `Quests` | 차례, 조건(장비 입기는 장비 칸), 수, 보상(골드, 아이템, 경험치) |
| `Strings` | 화면에 보이는 이름과 문장. 한국어와 영어 두 열 |

| 1–99 | 세션 | 로그인, 끊기, 연결 확인, 캐릭터 목록·만들기·들어가기·나가기 (있음), 로그아웃, 실패 알림(`ActionFailed`), 개발 명령 |
| 100–199 | 월드 | 이동, 시야 (있음), 표시 상태 변화(`EntityState`), 필드 전체에 가는 알림(보스의 등장과 자리, 보스의 죽음, 들어온 연결에 보내는 나와 있는 보스) |
| 200–299 | 전투 | 공격 시작·멈춤, 공격 동작의 시작, 스킬 사용, 진행 중인 일(`Progress`, `ProgressCancelled`), 피해, 효과, 발사체, 죽음, 부활, 범위 예고, 개체의 체력(피해가 아닌 까닭으로 바뀐 것을 1초마다 모아 보냄), 내 상태(체력, 마나, 전투 상태와 선공 표시가 끝나는 틱), 내 쿨다운 |
| 300–399 | 성장과 아이템 | 경험치, 능력치, 인벤토리 내용과 변화, 사용, 입기·벗기, 강화, 떨어뜨리기와 줍기, 스킬 배우기, 퀵슬롯, 상점, 창고, 펫(부르기와 넣기, 내 펫), 요청의 답(`RequestResult`) |
| 400–499 | 함께와 겨루기 | 채팅, 파티, 성향과 사망 페널티 |
| 500–599 | 생활 | 채집, 제작, 퀘스트 |

요청의 답(`RequestResult`)은 요청 번호를 실은 요청 모두(제작의 시작과 퀘스트 포함)가 함께 쓰고, 성공인지와 실패한 이유만 알립니다([요청 검증](#요청-검증)). 내용(강화의 결과, 배운 스킬)은 따로 패킷이 싣습니다. 채집과 제작의 진행은 진행 중인 일의 패킷이 알립니다([전투](#전투)).

## 저장

SQLite 하나에 둡니다. 언제 무엇을 큐에 넣고 어떻게 쓰는지는 [저장의 흐름](#저장의-흐름)에 있습니다.

| 테이블 | 내용 |
| --- | --- |
| `characters` | 계정(로그인 ID), 이름(대소문자를 가리지 않고 하나), 직업, 위치(있음), 레벨, 경험치, 체력, 마나, 골드, 성향, 가진 펫과 나와 있는지 |
| `items` | 주인, 있는 곳(인벤토리, 장비, 창고)과 칸, 아이템 번호, 수량, 강화 수치 |
| `skills`, `quickslots`, `quests` | 배운 스킬, 퀵슬롯, 퀘스트 진행 |

쿨다운, 효과, 선공 표시는 저장하지 않습니다([세션](#세션)의 다시 들어와도 남는 것). 저장 형식에 버전을 둡니다. 버전이 다른 데이터베이스를 만나면 옛 파일의 이름을 바꿔 두고 새 데이터베이스로 시작합니다(시연 서버라 옮기는 코드를 두지 않습니다).

## 최적화

리니지 라이크의 기술 과제는 한 화면과 한 서버에 사람이 많은 것입니다. 클라이언트 포트폴리오라 서버의 콘텐츠는 줄였지만, 사람이 많을 때 서버가 해야 하는 최적화는 합니다. 그것이 없으면 클라이언트가 200명을 그릴 일도 없기 때문입니다. 최적화는 **먼저 재고, 가장 큰 것부터 고치고, 같은 방법으로 다시 재서 전과 후의 수치를 남기는** 순서로 합니다. 재지 않은 것은 고치지 않습니다. 수치는 `docs/performance.md`에 잰 날, 커밋, 환경과 함께 남깁니다(키우기와 같은 방식).

### 한 것

방법은 [MANUAL](../MANUAL.md)에, 잰 날과 커밋이 붙은 기록은 [성능 수치](performance.md)에 있습니다.

| 무엇 | 수치 |
| --- | --- |
| Mac 패키지 크기 | 872 → 212 MB |
| Android 라이브러리(libprotobuf) | 145 → 11 MB |
| Android 셰이더 | 압축 전 두 벌 6.8 + 5.3 MB에서 OpenGL ES 3.1의 5.3 MB가 빠짐. 같은 콘텐츠로 APK의 전과 후는 재지 않았습니다 |
| 송신량 | 개체 하나 15바이트, 시야 55명에 클라이언트당 15,354 B/s |
| 틱 시간 | 봇 2,000명에 평균 15.4 ms(최대 23.5 ms) |
| 저장 | 2,000명의 위치에 4.8 ms |

### 서버에서 할 것

잰 값은 벽이 없는 평지에서 봇 2,000명(시야 평균 55명)이 걷기만 할 때의 것입니다. 맵을 넣은 뒤 같은 봇(격자를 읽어 서버와 같은 선 검사로 막힌 곳으로 걷지 않고, 막히면 돌아섭니다)으로 다시 잰 값(틱 평균 14.6 ms 가운데 시야 7.5 ms, 보내기 6.7 ms)은 `docs/performance.md`에 있습니다. 전과 후를 견주는 기준은 몬스터와 전투까지 있는 서버를 사냥하는 봇으로 잰 값입니다(재지 않았습니다).

| 대상 | 잰 값 | 방법 |
| --- | --- | --- |
| 직렬화 | 틱의 7.1 ms | 개체의 움직임을 틱마다 한 번만 인코딩해 두고, 보는 연결마다 그 바이트를 이어 붙입니다(보는 사람 수만큼 다시 인코딩하지 않습니다) |
| 시야 비교 | 틱의 7.0 ms | 플레이어마다 전체를 비교하지 않고 시야 칸에 들어오고 나간 개체의 목록만 봅니다(시야 칸을 옮긴 플레이어만 전체를 다시 봄). 움직임, 사건, 상태는 개체마다 둔 "나를 받은 연결"의 목록으로 보냅니다 |
| 할당 | 131 MB/s | 틱 버퍼와 틱 안의 목록을 풀에서 꺼내 씁니다(53). 54 뒤의 사냥하는 봇 62.0 MB/s가 13.1 MB/s(79% 감소)가 되어 GC가 멈춘 시간이 10초에 374 → 73 ms였습니다. 가장 긴 틱(약 15 ms) 안의 GC 몫은 5–7 ms이고, GC 설정은 재서 워크스테이션 + 동시 GC(기본값)를 골랐습니다 |
| 송신량 | 클라이언트당 15,354 B/s(한 달 43 GB). VPS에서는 CPU가 아니라 이것이 동접을 정함 | 이동을 바뀔 때만 알립니다([공간](#공간)의 이동 알림). 목표는 절반 아래입니다. 54에서 곧게 걷는 봇 17,015 → 2,736 B/s, 사냥하는 봇 23,065 → 5,385 B/s(77–84% 줄어 KVM 4 동접 252–337명 → 948–1,613명)였습니다 |
| 시야의 경계 | 재지 않음 | 나가는 기준을 들어오는 기준보다 8 m 넓게 둡니다([공간](#공간)의 시야의 경계). 보는 쪽이 시야 칸을 넘을 때 생기는 들어옴·나감도 재고, 크면 보는 쪽의 중심 시야 칸도 새 칸으로 8 m 넘게 들어갔을 때 바꿉니다 |
| 사람이 몰린 곳 | 봇 500명을 한곳에 모으면 클라이언트당 27,431 B/s(한 달 75 GB) | 시야 인원 상한(200)을 둡니다([과부하 때](#과부하-때)). 55에서 11,205 B/s(59% 줄어 한 달 32 GB, KVM 4 동접 214명 → 497명), 틱 평균 4.07 → 4.32 ms였습니다 |
| 몬스터 AI | 몬스터 차례 평균 0.06–0.08 ms(몬스터 201마리, 봇 500–2,000명) | 플레이어 없는 곳의 몬스터는 계산하지 않습니다([틱의 차례](#틱의-차례). 56). 봇 500명을 한곳에 모으면 0.057 → 0.018 ms, 필드에 흩은 2,000명은 그대로였습니다. 소환수는 잠들지 않으므로 소환수 100의 틱 시간을 따로 잽니다 |
| 저장 | 2,000명의 위치를 틱 스레드에서 쓸 때 4.8 ms | 저장 스레드에서 바뀐 플레이어만 씁니다([저장의 흐름](#저장의-흐름)). 57에서 2,000명의 60초 묶음이 저장 스레드에서 30 ms 안팎, 큐는 늘 하나까지, 틱의 사본은 60초 틱에 2 ms 안이었습니다. WAL 체크포인트는 커밋 안에서 떼어 쓰기 묶음마다 저장 스레드가 따로 돌리며 0.3–2.2 ms입니다 |
| OS의 한도 | 확인하지 않음 | VPS에서 열 수 있는 파일 수와 소켓 버퍼가 연결 수보다 먼저 막히지 않는지 확인합니다 |

무엇이 MMO 서버의 일반적인 기술인지, 각각을 넣는지, 넣지 않은 것의 이유는 [MMO 서버 기술과 적용 여부](#mmo-서버-기술과-적용-여부)의 표에 있습니다.

### 클라이언트에서 할 것

목표는 한 화면에 캐릭터 200명입니다. 프레임 목표(휴대폰 30, PC 60)는 기기에서 처음 잰 뒤에 정합니다.

| 대상 | 방법 |
| --- | --- |
| 게임 스레드 | 다른 캐릭터는 액터의 틱을 끄고 관리자 하나가 한 번에 위치를 넣습니다. 이동 컴포넌트를 두지 않습니다 |
| 애니메이션 | 화면 밖과 그리지 않는 캐릭터는 갱신하지 않습니다(있음). Animation Budget Allocator로 먼 캐릭터의 갱신을 줄이는 것은 Mac에서 200명이 게임 스레드 0.7 ms라 넣지 않았고, 휴대폰을 재면 다시 봅니다(59) |
| 그리기 | 메시 LOD(Mac에서 캐릭터의 기본 패스가 0.5 ms라 넣지 않음. 59), 먼 캐릭터의 그림자 끔, 그릴 캐릭터 수(있음). 그릴 캐릭터는 시야 인원 상한과 같은 차례([과부하 때](#과부하-때))로 고릅니다. 수에는 다른 플레이어만 세고, 몬스터, NPC, 채집물, 바닥 아이템은 모두 그립니다. 수에 들지 못한 플레이어는 이름표도, 그 플레이어의 소환수와 펫도 그리지 않습니다. 품질 단계마다의 값은 [화면](#화면) |
| 환경 | 같은 메시(나무, 바위, 건물, 울타리)를 인스턴스로 묶어 그리고, 종류마다 그리지 않는 거리를 두고, 메시 LOD를 씁니다. 전과 후를 잽니다 |
| UI | 이름표와 피해 숫자를 한 층에서 풀로 그리고, 인벤토리와 창고의 목록은 보이는 줄만 만듭니다 |
| 끊김과 메모리 | 액터(몬스터, 바닥 아이템, 이펙트)를 풀에서 쓰고, 에셋을 비동기로 불러오고, 패킷을 Protobuf Arena에 풀어 프레임마다의 할당을 없앱니다 |
| 시작 시간 | 시작부터 로그인 화면까지의 시간을 잽니다 |
| 발열 | 프레임 상한을 설정에 둡니다 |

### 재는 방법

- **서버**: 10초마다 찍는 로그(틱 평균과 최대, CPU, 송신량, 할당, GC)와 `server/tools/load-test`의 봇입니다. 봇은 격자를 보고 걷고, 사냥하고 부활하고, 줍고 물약을 쓰고, 한곳에 모입니다. 마법사 봇은 소환수를 부른 채 사냥합니다.
- **길찾기**: 서버의 A* 한 번(살피는 범위 안에서 가장 나쁜 경우)의 시간과 할당, 몬스터 100마리가 같은 틱에 길을 찾을 때의 틱 시간, 클라이언트가 필드의 끝에서 끝까지 한 번 찾는 시간을 잽니다. 시험 구현으로 잰 값은 [성능 수치](performance.md)에 있고, 실제 몬스터로는 30의 뒷부분이 다시 봅니다.
- **Live의 봇**: 시연 서버에는 사냥하는 봇 20명을 같은 VPS에서 늘 띄워 둡니다. 20명 가운데 10명은 체험 캐릭터(레벨 20)로 만들어 사냥터 2와 3에서 사냥합니다(혼자 온 사람이 PK할 상대가 되게). 봇은 맞아도 반격하지 않고 하던 사냥을 합니다. 봇은 파티 초대를 받으면 수락하고, 5분 동안 초대한 플레이어를 10 m 안에서 따라 걸으며 그 플레이어가 치는 몬스터(그 플레이어가 공격자인 `AttackSwing`의 대상)를 함께 친 뒤 파티를 떠납니다(혼자 들어온 사람이 파티를 해 볼 수 있게). 플레이어는 치지 않습니다. 봇 프로세스와 서버의 CPU를 재서 남깁니다(재지 않았습니다).
- **클라이언트**: Unreal Insights(CPU와 메모리 기록), `stat unit`, 실제 휴대폰의 Development 빌드입니다. 봇 200명을 한 화면에 모아 잽니다.
- **비용**: 송신량을 월 GB와 VPS의 동접으로 바꿔 적습니다.
