# M2 1단계: 전투 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 메인 화면에서 영웅이 몬스터를 자동으로 잡고 보스에 도전해 다음 스테이지로 넘어가며, 그 결과를 서버가 같은 시뮬레이션으로 확정한다.

**Architecture:** 전투는 `game-core`의 결정적 시뮬레이션이고 저장 데이터에는 경계 체크포인트(`battle` 슬라이스)만 남는다. 정산·보스 도전·스테이지 이동은 커맨드 리듀서라 클라이언트가 예측하고 서버가 같은 코드로 확정한다. 클라이언트는 체크포인트에서 시뮬레이션을 프레임마다 진행해 이벤트를 화면 지시로 바꾸고, C#은 도형 배우와 데미지 숫자의 움직임만 그린다.

**Tech Stack:** TypeScript(ESM, strict), vitest, node:test(data-tool), exceljs, Svelte+Tauri(formula-tool), Rust(serde), Unity 6000.6 + PuerTS 3.0.3, C# 9.

**Spec:** `docs/superpowers/specs/2026-10-13-m2-battle-design.md`

## Global Constraints

- 주석과 문서 주석은 한국어, 테스트 이름·오류·로그 메시지·커밋 메시지는 영어(AGENTS.md).
- C#은 `client/AGENTS.md`의 "C# 코딩 규칙"(Microsoft 규칙, `_camelCase`/`s_camelCase`, C# 9, `///` 한국어 주석)을 따른다.
- 커밋하지 않는다. 변경은 작업 트리에 남기고, 커밋은 사용자가 요청할 때 컨트롤러가 한다. `git switch/checkout/merge/stash`를 쓰지 않는다(Unity가 열려 있음).
- 생성 파일(`shared/data-schema/src/tables/`, `shared/data-schema/data/`, `shared/game-core/src/formulas.ts`, `client/TypeScript/types/csharp.d.ts`)은 손으로 고치지 않는다.
- `game-core`는 호스트 API(시계, 타이머, `Math.random`, `Date`)를 쓰지 않는다. 결정성: double의 `+ − × ÷`, 비교, `Math.max/min/floor/round`, big-number 연산만 쓰고, 결과를 정하는 반복은 배열 순서만 쓴다(스펙 4.6).
- 시뮬레이션 상수: `TICK_MS = 100`, `APPROACH_TICKS = 5`, `REVIVE_TICKS = 30`, `MAX_SETTLE_TICKS = 6000`.
- 클라이언트 정산 주기 `SETTLE_INTERVAL_MS = 60_000`.
- `Opcode.BattleSettle = 101`, `Opcode.BossChallenge = 102`, `PROTOCOL_VERSION = 2`, 저장 형식 2.
- 와이어 스냅숏의 기존 항목은 갱신(`-u`)하지 않는다. 새 항목만 더한다.
- 각 작업을 끝내기 전에 루트에서 `npm run typecheck`와 `npm test`를 통과시킨다.

## Review Focus

1. 클라이언트와 서버의 `now`가 몇 ms 어긋나 서버가 예측보다 경계 하나 뒤의 체크포인트를 확정하는 경우: 그 체크포인트는 보이는 전투가 지나온 상태이므로 `reset` 없이 이어 가야 한다(Task 7 테스트).
2. 앱이 몇 분 멈췄다 돌아와 한 프레임에 수천 틱이 밀린 경우: 데미지 숫자 수천 개를 쏟지 말고 조용히 따라잡은 뒤 `reset` 하나만 내야 한다(Task 7 테스트).
3. `Heroes.skillIds`를 바꿔 저장된 `cooldowns` 길이가 스킬 수와 다른 경우: 모자라면 0으로 채우고 남으면 버려야 하며 던지지 않는다(Task 5 테스트).
4. 스테이지 데이터가 비정상인 경우(`monsterIds`가 비고 보스도 없음, `bossKillCount = 0`): 무한 루프 없이, 전자는 스테이지 ID를 담은 오류로 던지고 후자는 첫 경계에서 바로 보스/클리어로 가야 한다(Task 5 테스트).
5. 보스 도전 중 연결이 끊겼다 재개되어 저장 데이터가 통째로 바뀐 경우: 보이는 전투가 새 체크포인트로 다시 맞춰지고, 보스 HUD(남은 시간, 버튼)가 새 상태를 따라야 한다(Task 7, Task 9 테스트).
